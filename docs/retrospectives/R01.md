# R01 GC — 아담 선행 코어 개발 사이클

범위: Unity 설치 전 C# 코어 구현·독립 리뷰·로컬 시험. 실제 게임 라운드 플레이 후 회고가 아니다. 사용자 지시인 라운드별 GC 후 GitHub 업로드에 따라 이 기록을 검증된 코어 변경과 함께 공유한다.

## 근거와 처리

| 분류 | 실제 근거 | 처리·남은 일 |
|---|---|---|
| 코드 결함 | 독립 리뷰 HIGH: 피해 API가 적을 제거한 뒤 처치 보상 누락 | `AdamSession.Hit` 단일 경로, 조회용 `IWaveView`, 회귀 시험·실제 변이·후속 리뷰로 해결 |
| 저장 결함 | 독립 리뷰 HIGH: 완료 후 남은 레벨업을 복원하지 못함 | 다음 라운드 대기 상태의 선택 복구, 실제 저장 왕복 시험·기존 거절 변이로 검출, 후속 리뷰 해결 |
| 검증 누락 | 독립 리뷰 MEDIUM: NaN 적 체력 복원 | 유한 수 검사·NaN/Infinity 회귀·실제 NaN 허용 변이 검출 |
| 기능 연결 누락 | 독립 리뷰 MEDIUM: 선택 가능한 보조 효과가 공격 수치에 연결되지 않음 | 장비→공격 프로필/이동/반격 수치 연결 및 통합 시험, 후속 리뷰 해결 |
| 콘텐츠 계약 | 콘텐츠 담당과 성장 담당의 보조 ID 6종 불일치 | 공통 ID로 수정, 검사기에 잘못된 ID 음성 입력, 계약 문서 보강 |
| 생성 경계 | 지연 생성 미소진 상태를 170초 직후 완료할 수 있던 초안 | 모든 예정 적을 생성/처치하지 못했으면 180초까지 대기. 조기 종료 회귀를 실제 변이 시험으로 검출 |
| 공격 경계 | 빠른 연사에서 이전 연사와 다음 주기가 겹칠 수 있음 | 시간순 이벤트 병합과 프레임 분할 회귀 시험 |
| 저장소 패키징 | 기존 Unity용 *.csproj ignore가 새 코어 프로젝트 파일까지 숨김 | 루트 Unity 생성 프로젝트만 제외하도록 좁힘. staged 파일 목록으로 재확인 |
| SDK 환경 | 기존 C# SDK 부재 | 공식 설치 스크립트로 전용 로컬 SDK 설치, 전역 PATH/셸 설정 미변경. 첫 SDK 실행의 개발 인증서 생성 메시지는 관측됐으나 신뢰 등록은 하지 않음. 이후 wrapper에서 해당 자동 생성을 비활성화 |
| 증거 보존 | 최종 독립 리뷰에서 변이 로그의 고정 경로 발견 | 실행별 고유 출력 폴더로 수정하여 과거 검증 근거의 덮어쓰기를 방지 |

위 코드/도구 수정은 승인된 R01 구현·리뷰 수정 범위에서 완료했다. 별도 전역 학습 규칙을 추가한 것은 아니다.

## 모델·토큰·위임 네 영역

- 모델 적합성: 데이터·성장 계산을 별도 구현 담당에게, 저장·세션 통합을 주 담당에게 배정하고 읽기 전용 리뷰를 분리했다. 모두 현재 세션의 상속 모델을 사용했다. 호출별 모델 ID/추론 설정의 실제 telemetry는 미측정이며 모델이 자동 변경됐다고 주장하지 않는다.
- 총토큰: 입력/출력/캐시/reasoning·전체 비용·단일 실행 기준선이 제공되지 않아 미측정이다. 절감률을 계산하지 않았다. 독립 리뷰가 실제 결함 4건을 검출한 품질 기여는 확인했다.
- 위임 목적: 콘텐츠와 성장 파일 소유를 분리해 병렬 작업했다. 공유 검사 러너 충돌을 막기 위해 담당자는 격리 사본에서 검증했고 최종 통합 검사는 주 담당이 실행했다. 별도 총괄/요약 에이전트는 만들지 않았다.
- 추가 개선: 공통 콘텐츠 ID를 먼저 확정하고 세션 API의 공격/선택/저장 통합 시험을 초기에 작성하면 재작업을 줄일 수 있다. 다음 단계에서 실제 장비→타깃/충돌까지 이어지는 Unity 시험으로 확장해야 한다. 효과는 다음 동일 조건 실행으로 확인하며 아직 비용 최적화 성과로 세지 않는다.

## GC 상태 진단과 적용 경계

기존 harness-gc의 `refine.py --scope global gc --json`을 읽기 전용 실행하고 원문은 무시되는 로컬 `.local/`에 보존했다. 전역 규칙 감사·승격 후보·승격 후 재발·병합 후보를 진단했으나 프로젝트와 무관한 개인 규칙·경로는 이 공개 문서에 복제하지 않는다. 프로젝트 학습 상태가 아직 없으므로 임의 init/fallback/apply는 하지 않았다.

이번 관측의 판단 학습 후보는 **독립 프리미티브 시험 통과를 세션의 실제 명령 경로 통과로 간주하지 말 것**이다. 근거는 위 피해→처치와 완료→저장→재개 결함이다. 이미 코드 회귀 시험으로 도구화했으므로 새 전역 문장 추가는 보류한다. 기존 전역 승격 후 재발 후보도 이번 Unity 코어 사례와 동일성을 확인하지 못했으므로 reinforce/promote하지 않았다. 문장보다 실제 통합 시험을 우선한다.

규칙/엔트리 반영·승격·병합·삭제는 사용자가 고른 구체 후보만 수행한다. 향후 GC에서 같은 결함이 재발하면 현재 회귀 시험을 우회한 입력 경로를 먼저 찾고 검사기를 보강한다. 검사 자체를 통과시키기 위한 예외는 추가하지 않는다.
