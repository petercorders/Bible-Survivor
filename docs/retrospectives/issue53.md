# #53 인수 회고

- 최초 원장의 공백을 단계별로 집계했다. 별도 Editor 사본 없이 후보 실행 증거 재사용, Core 인수 시험 및 격리 Mac Player 확인을 진행했다.
- 런타임 효과 조회, 구매 조건, 실전 발동과 재생을 별도 열로 기록해 거래와 전체 조합의 성공이 개별 발동으로 집계되지 않게 했다.
- 첫 주기 변이가 정수로 추론되어 컴파일에서 실패했다. 타입을 보존해 제품 동작 단정이 실제로 실패하는지 재실행했다.
- 이전 포인터 미관측이 같은 바이너리에서 재현됐다. 다음 회차는 물리 입력 호스트를 먼저 확보하면 실패한 배경 포인터 재시도를 줄일 수 있다.
- 장치·참가자·Steam 접근 보류 조건은 인수 보고서에 남겼다. 모델과 토큰은 로컬 사용량 기준점으로 기록했다. 청구액은 미측정이다.

## 2회차

- 실제 타격과 피격을 소수의 고정 전투 준비 상태에 묶었다. 구매 랭크 한 단계씩 비교하고 원장 행별로 독립 시험 이름을 남겼다.
- R09 방어 분류의 첫 준비 상태에는 무작위 RunId를 사용해 중간 보상 장비가 달라지는 경우가 있었다. 후보 코드를 유지한 채 RunId를 고정하고 동일 장비에서 재실행했다.
- 활성·비활성의 차이를 구분하기 위해 R09 본체 접촉과 사슬에 각각 두 방어 노드를 적용하고, R03 보스 방어는 일반 웨이브 피격과도 비교했다.
