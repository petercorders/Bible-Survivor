# R50 회고

여호수아를 R42에서 끝내고 사사기를 R43–R50까지 설치했다. R40에서 일반화해 둔 공통 라운드 생성기, 책 진입 경로, "R21부터 세 라운드마다 보스" 저장 검증이 그대로 맞물려 Core 변경은 책 정의·보스 세 개·진입 하나에 그쳤다. 여호수아 라운드 ID 범위를 설치 끝 상수 대신 책 끝 상수(R42)로 옮겨 R37–R40 지문을 유지했다.

이전 빌드 저장은 R30 때와 같은 출처 방식을 썼다. R40 QA 앱이 직접 만든 R40 완료 저장과, 바꾸기 전 코드에서 출력한 R01–R40 지문 40개를 고정 파일로 두었다. 지문 출력은 임시 콘솔 프로젝트로 했고 R01–R30이 기존 고정 파일과 같은지 먼저 대조했다.

R40 회고의 "일괄 치환 예상 개수 오산"을 피하려고, Unity 시험의 'R41 미설치' 단정을 모양별로 먼저 세어 8가지 46곳을 고정 개수로 바꿨다. 이 부분은 재작업이 없었다. 그러나 `[TestCase(37,5,1,4)]`처럼 라운드와 총 라운드가 숫자 인자로만 들어간 기대값은 그 검색에 걸리지 않아 첫 EditMode에서 3건 실패로 드러났다.

Unity 격리 사본을 처음 만들 때 저장소의 `art/`와 프로젝트의 `.adam-rounds-qa` 표식을 빠뜨려 EditMode 5건이 경로 오류로 실패했고 QA 빌드가 한 번 거절됐다. R40 사본 구성을 보고 맞췄다. 사본 준비를 스크립트로 두면 같은 마찰이 없어진다.

변이 6개를 격리 사본에서 모두 검출했다. 세 개는 의도한 단정보다 다른 방어선(저장 수명 검증, R40 저장 이어 하기 시험의 후보 저장 검증, 새 저장 읽기 거절)이 먼저 막았고 진행 문서에 그대로 적었다. 처음 문서에는 두 번째 방어선을 "재개 시 체크포인트 대조"로 잘못 적었는데, 독립 리뷰가 변이 로그의 실제 예외(새 버전 필요)와 대조해 바로잡았다.

독립 코드 리뷰는 CRITICAL·HIGH 없이 MEDIUM 1건(시험 기대값 수정과 시험 필터가 커밋 밖)과 LOW 4건을 냈다. 커밋 밖 변경은 문서와 한 커밋으로 묶었고, 변이 정의는 증거에 남겼다. 사사기 범위가 설치 끝 상수에 묶인 점과 R41–R50 수치를 고정 파일로 묶지 않은 점은 진행 문서의 다음 단계 할 일로 적었다. 부분 설치 완료 문구를 정적 호출로만 확인한 점은 R40과 같은 수준이라 그대로 두었다.

PR에서 남긴 두 건도 고치라는 요청을 받아 리뷰 반영 1회차로 고쳤다. R41–R50 값은 이 빌드의 R01–R50 지문 고정 파일로 묶었고, 책 완료 화면의 계산은 게임 화면 안에서 Host 기반 함수로 옮겨 Host 시험이 같은 경로를 지나게 했다. 각각 변이 2개로 새 단정이 잡는 것을 확인했다. '선례와 같은 수준'은 남길 이유로 약했다. 둘 다 고치는 비용이 작았으므로, 다음에는 같은 판단이 들 때 먼저 고치는 쪽을 고른다.

새 아트는 만들지 않고 검수된 출애굽기 R06 스프라이트와 책별 지형 색조를 재사용했다. 구현·통합은 Claude Opus 5.5(요청 모델과 실제 모델 같음)로 진행했다. 사용량 기록 도구가 이 세션 로그를 읽지 못해 사용량은 미측정이다. 비용과 절감률도 계산하지 않았다.
