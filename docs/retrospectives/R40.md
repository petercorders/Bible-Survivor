# R40 회고

신명기·여호수아 라운드 정의는 민수기 공식을 전역 오프셋으로 연장한 공통 생성기로 만들었다. 민수기 정의 코드는 건드리지 않고 상한만 R30으로 고정해 R22–R30 지문을 유지했다. R30 빌드에서 뽑은 지문 30개와 그 빌드가 만든 R30 완료 저장을 시험 고정 파일로 두어, 새 빌드가 이전 저장을 바꾸지 않고 읽는지 매번 확인한다. 책 진입은 기존 민수기 진입의 저장 후보·재시도 경로를 그대로 재사용했고, 새 책 경계 두 곳(R31·R37)을 일반 다음 라운드에서 막았다.

설치 끝이 R30에서 R40으로 바뀌면서, "다음 미설치 라운드는 31"을 전제로 쓴 기존 Unity·Core 시험 39곳을 R41로 옮겼다. 일괄 치환 전 예상 개수를 36으로 잘못 세어 스크립트가 멈췄고, 바뀐 곳을 하나씩 확인한 뒤 39곳으로 고쳤다. Core만 커밋하려다 Unity용 Core DLL 동기화가 빠져 pre-commit의 portable 검사가 커밋을 막았다. Core 변경과 DLL·Unity 변경을 한 커밋으로 묶어 해결했다.

격리 사본에서 변이 6개를 모두 검출했다. 이 중 2개는 의도한 단정보다 다른 방어선이 먼저 막았다. 보스 기록이 R30 뒤로 이어지지 않는 옛 구조는 저장 수명 검증이, 신명기 완료 전 여호수아 진입은 재개 시 체크포인트 대조가 거절했다. 진행 문서에는 어느 방어선이 잡았는지 그대로 적었다. base에 이미 있던 `tools/check_boss_mutations.py`의 `normal_uses_old_finish` 원문이 현재 코드와 맞지 않는 것을 발견했으나, 이번 범위 밖이라 고치지 않았다.

독립 리뷰는 코드 결함 없이 진행 문서의 과한 주장 하나(LOW)를 지적했다. 설치된 보스 라운드 기록의 개수·순서 손상은 미래 저장 거절이 아니라 기존 손상 복구(백업 읽기) 경로를 탄다. 문서를 실제 동작에 맞게 좁혔고 코드는 바꾸지 않았다.

새 아트는 만들지 않고 검수된 출애굽기 R06 스프라이트와 책별 지형 색조를 재사용했다. Fable은 사용하지 않았다. 구현·통합과 리뷰는 Claude Opus 5.5(요청 모델과 실제 모델 같음)로 진행했다. 리뷰는 같은 모델의 별도 에이전트가 맡았다. 사용량 기록 도구가 이 세션 로그를 읽지 못해 사용량은 미측정이다. 비용과 절감률도 계산하지 않았다.
