# #57 회고

- Unity의 제품명과 애플리케이션 지원 경로를 유지한 채 macOS 창 제목과 배포 이름을 바꿨다. 여러 세이브 위치가 있어도 Unity의 기존 선택을 사용했다.
- 첫 빌드가 생성한 plist의 DOCTYPE에 빈 내부 서브셋이 붙었다. macOS 파서의 검사 실패를 재현하고 수정한 뒤 새 앱을 빌드했다. 다음 번들 메타데이터 변경은 `plutil -lint`와 `codesign --verify --deep --strict`를 빌드 직후 이어서 실행한다.
- 설정과 진행을 하나의 격리 환경에서 재현하려다 환경설정 서비스 차단으로 이전 화면 크기가 적용되지 않았다. 환경설정용 격리 도메인을 마련해 저장 파일과 화면 설정을 각각 대조하고 검증 범위에 기록했다.
