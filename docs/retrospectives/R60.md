# R60 회고

사사기를 R51에서 끝내고 룻기 R52–R54, 사무엘상 R55–R60을 설치했다. R50에서 남긴 두 가지 다음 단계 할 일(사사기 범위를 책 끝 상수로 분리, R50 완료 저장 고정 파일)을 이번 단계의 출발점으로 삼았다. 공통 라운드 생성기, 책 진입 경로, "R21부터 세 라운드마다 보스" 저장 검증이 그대로 맞물려 Core 변경은 책 정의 두 개·보스 네 개·진입 두 개와 사사기 끝 상수에 그쳤다. 책이 두 권이라 Unity 배관(설치 여부, 진입, 재시도 모달, 완료 문구, 머리띠, 지형 색, 보스 이름, 그림자)은 두 벌 필요했다.

이전 빌드 저장은 R50 QA 앱이 직접 만든 R50 완료 저장을 바이트 그대로 복사해 썼다. R01–R50 지문은 R50 단계에서 고정한 파일을 그대로 비교했고, 새 R01–R60 지문을 출력할 때 앞 50줄이 그 파일과 같은지 시험 밖에서 한 번 더 대조했다.

R50 회고의 "숫자 인자로만 들어간 기대값을 놓침"을 피하려고 Unity 시험의 'R51 미설치' 단정을 모양별로 세어 바꾸고, 책 머리띠 `[TestCase]`의 사사기 총 라운드(8→9)를 미리 고쳤다. 그래도 R15 시험의 `RoundNumber=51,Stage="round_settlement"` 한 곳을 다섯 모양 목록에서 빠뜨려 첫 EditMode에서 1건 실패했다. 모양 목록을 사람이 정하면 빠지는 모양이 생긴다. 다음에는 `RoundNumber ?= ?<설치 끝+1>` 처럼 숫자 자체로 먼저 전부 나열한 뒤 모양을 나눈다.

Unity 격리 사본은 R50 사본을 APFS 복제로 떠서 바뀐 파일만 덮었다. 복제 전에 R50 사본의 추적 파일이 R50 커밋과 같은지(다른 것은 Unity가 다시 쓴 메타·프로젝트 설정뿐) 대조했다. R50 회고의 사본 구성 마찰(art/·QA 표식 누락)은 이 방식으로 생기지 않았고, Library 캐시 덕에 EditMode 한 번이 약 1분 반이었다. QA 빌드가 장면에 드라이버를 넣어 저장하므로, 변이 확인 전에 QA 파일을 빼고 장면을 추적 원본으로 되돌렸다.

변이는 Core 9개(격리 clone)와 Unity 4개(격리 사본)를 모두 검출했다. Unity 변이는 변이마다 원복 뒤 사본 파일이 저장소 파일과 같은지 대조했다. 두 개(앞 책 완료 전 진입)는 의도한 단정보다 후보 저장 검증이 먼저 막았고, R60 보스 HP 변경은 지문 고정 시험만 잡아 진행 문서에 그대로 적었다.

R16–R60 고정 장비 좌표 전투에서 후반 라운드의 처치 수가 크게 줄었다(R16 1,132 → R59 127). 고정 장비·체력의 기술 검증이라 밸런스 판단 근거는 아니지만, 자연 플레이 밸런스를 볼 때 첫 확인 대상이다.

새 아트는 만들지 않고 검수된 출애굽기 R06 스프라이트와 책별 지형 색조를 재사용했다. 구현·통합은 Claude Opus 5.5(요청 모델과 실제 모델 같음)로 진행했다. 사용량 기록 도구는 Codex 세션 ID를 요구해 이 세션을 읽지 못했으므로 사용량은 미측정이다. 비용과 절감률도 계산하지 않았다.
