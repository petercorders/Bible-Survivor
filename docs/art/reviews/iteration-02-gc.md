이번 QA는 제작자 입력 함수에 의존하지 않고 정상1+오류25를 직접 만들었다. 이전에 실제로 통과한6개 오류는 **옛 checker 전체**와 새 checker에 같은 입력으로 재실행하여0→1을 확인했다. 이 사례는 기존 원칙 “회귀 자체를 재현한 변이의 실패를 본다”를 프로젝트 테스트로 실현한 것이며, 유사 문장을 전역에 중복 추가하지 않는다.

## 증거와 도구 적용 상태

- 정상/음성: `iteration-02-review.md`의26케이스와 코드별 exit 표. 입력 해시/JSON 정합성을 유지한 오류도 별도로 확인했다.
- 검증: 임시 verify_all 최종0, 제작자 오류41모두1, 검사기 제거변이5모두검출. 변이 존재검사 제거가 예외를 낸 경우까지 구분해 테스트가 실패한 것을 읽었다.
- 재생성:83파일 완전동일. PNG79개/pixel-source/tiles·assets 배열이 반복01과 불변이므로 이전 시각 QA를 재사용. 바뀌지 않은 장면을 다시 그리거나 새 화면 전부를 열지 않았다.
- 실제 반영된 재발 방지 도구는 `check_art03.py`, `contract_v3.json`, `test_check_art03.py`, `checker_mutations_iter02.py`, `verify_all.py`다. QA가 수정한 것이 아니라 수정본을 독립 검증했다.
- 전역 상태 변경 후보보다 프로젝트 검사기의 현재 강제를 우선한다. CI/pre-commit 연결은 **coordinator 후속 작업**이며 설치됐다고 쓰지 않는다.
- 추가 QA 집계 스크립트에서 정상 baseline 행에 `pass` 키가 없음을 놓쳐 KeyError가 한 번 났다. 결과 JSON 구조를 확인해 정상행과 오류행을 분리하고41오류의 pass값을 다시 집계했다(41건 전부True). 검사 CLI/산출물 문제로 잘못 보고하지 않았다.

## 한계와 다음 변경의 재검사

현재 판정은 해시가 고정된 오프라인 production-draft에만 적용한다. 후속 outline 폰트/TMP/Unity 임포터 패치가 들어오면 바뀐 폰트 role/파일/SHA/라이선스와 실제 엔진 렌더를 다시 확인한다. Bitmap glyf가 비어 있는 사실을 검사기의 파일/SHA PASS로 덮지 않는다. Unity/모바일은 이번에 NOT_RUN이며 설치·프로젝트 존재를 실행 성공으로 바꾸지 않는다.

아트 생성의 출처도 분리한다. 이번은 계약·검사기 수정이며 실제 Claude Design 생성은 수행하지 않았다. 로컬 source/scripts 출력·Pillow review/UI 합성·Design 캔버스 사본 존재는 각각 다른 근거다. 공개 시 canvas·캐시·개인경로·임시로그 제외는 coordinator가 확인한다.
