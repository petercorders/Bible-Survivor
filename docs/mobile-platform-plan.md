# PC·모바일 공동 개발 고려 사항

상태: 모바일 앱도 지원할 수 있도록 초기 설계에 반영한다는 사용자 요구를 기록한 계획이다. 실제 모바일 구현·실기기 검증·출시 완료를 의미하지 않는다. Android와 iOS를 계획 대상으로 두되 지원 OS/기기/태블릿 범위·최소 사양·출시 순서는 후속 계획에서 정한다.

## 구조

- 전투·성장·웨이브·보상·영구 스킬 데이터와 저장 스키마는 공통으로 사용한다. 키보드·터치 입력은 공통 이동 벡터와 메뉴 동작으로 전달하고 전투 코드에 PC 키를 직접 의존시키지 않는다.
- 첫 전투 시제품은 PC에서 빠르게 검증하되 첫 모바일 실행·입력·화면·성능 검증을 창세기 콘텐츠 확대 이전에 배치한다. PC 통과가 모바일 통과를 뜻하지 않는다.
- 장치 성능에 따라 시각 효과·파티클·표시 품질을 조절하되 몬스터 예산·충돌·피해·보상 등 게임 규칙은 품질 옵션으로 임의 변경하지 않는다.

## UI/UX

- 가상 조이스틱/드래그 이동은 후보이며 초기 터치 시제품으로 선택한다. 자동 공격은 유지한다. 가로/세로 화면 방향은 아직 미정이며 전투 시야와 손가락 가림을 비교한다.
- 안전 영역·노치·다양한 화면 비율·글자 크기·터치 영역을 확인한다. 스킬트리 420종을 한 화면에 압축하지 않고 확대·이동·선행 조건 확인이 가능한 방식을 검토한다.
- 메뉴/레벨업/보스 보상을 누른 손가락 입력이 전투나 다음 화면으로 전달되지 않도록 입력 전환을 검증한다. 멀티터치·포커스 손실·중복 선택을 다룬다.

## 앱 중단·저장

- 앱 비활성화/전화/잠금/백그라운드에서 전투 시간과 입력을 정지하고, 복귀 시 시간 점프·즉시 피격·자동 선택이 없도록 한다. 실제 일시정지 정책은 시제품 계획에서 확정한다.
- OS 강제 종료는 사망과 구분한다. 기존 라운드 완료 저장 및 보스 보상 중복 방지 원칙을 유지한다. 전투 도중 재개/롤백 시점, 즉시 반영 골드의 저장 주기·원자적 기록·재실행 중복 방지는 구현 전에 구체적으로 결정하고 시험한다.
- 기기별 로컬 저장부터 검증하며 클라우드 저장/계정/PC와 모바일 간 진행 동기화는 별도 미확정 기능이다.

## 성능·리뷰

- 목표 기기와 프레임 예산을 먼저 정하고 실기기에서 전투 초반/최대 밀집/보스/장시간 실행을 측정한다. CPU/GPU 프레임 시간·GC·메모리·발열에 따른 지속 성능을 기록한다. 평균 FPS만으로 완료 판단하지 않는다.
- UI/UX와 성능 리뷰는 PC/Android/iOS별 상태를 분리한다. 실제 기기나 실행 환경이 없으면 해당 검증은 NOT_RUN/BLOCKED로 기록한다.
- 스토어 계정·서명·배포 모듈·구매/광고·출시 심사는 실제 출시 범위 결정 후 준비한다. 지금은 구매·광고·계정 연동을 기능 범위에 추가하지 않는다.
