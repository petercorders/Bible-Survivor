# 여호수아 R41–R42와 사사기 R43–R50

이전 버전의 R40 아이 성 완료 저장은 그대로 읽힌다. R40 완료 화면에서 다음 라운드로 진행하면 여호수아 R41을 이어 하고, R42 세겜 언약을 끝낸 뒤 사사기 시작을 명시적으로 선택하면 R43을 진행한다. 사사기 진입이 저장에 실패하거나 결과를 확인하지 못하면 완료 화면과 기존 저장을 유지하며 같은 operation으로 다시 시도한다. 진입 시 기존 도전 ID, 골드, 성장, 장비와 보상 기록을 승계한다. R50 삼손과 사자를 끝내면 완료를 저장하며, 다음 체크포인트 번호 51에는 진입할 수 없다.

## 결정 기록 (초기 수치)

모두 개발 초기 수치이며 자연 플레이 밸런스로 확정한 값이 아니다. 2026-11-20 이슈 #5에서 R40 방식을 따르는 추천안으로 정했다.

- 책 배분: 여호수아를 6라운드(보스 R39·R42)로 마치고, 사사기를 9라운드 책으로 두되 R50(일반 라운드)에서 설치를 멈췄다. 책 길이가 3의 배수이고 보스로 끝나는 흐름, R21부터 세 라운드마다 보스인 흐름, 설치 끝을 일반 라운드로 둔 R20·R40 선례를 따랐다.
- 라운드 수치: 민수기 공식을 전역 오프셋 `o = 라운드 − 22`로 계속 연장했다. 경험치 7200+200o, 완료 골드 420+20o, 적 생성 1560+60o, 체력 440+20o / 295+14o / 1070+35o, 3라운드 단위로 빠른 적 비율을 교대한다. 여호수아 접촉 피해는 R37–R40과 같고, 사사기는 책마다 1씩 올리는 규칙대로 18/17/22다. 사사기 속도는 여호수아보다 0.02(무거운 적 0.01) 빠르다.

## 저장과 기록

- 기존 R01–R40 지문과 과거 보상 필드를 그대로 유지한다. R40 빌드 코드에서 뽑은 R01–R40 지문 40개와, R40 빌드의 QA 앱이 직접 만든 R40 완료 저장을 고정 파일로 두고 새 빌드와 비교한다.
- 이 빌드의 R01–R50 지문 50개도 고정 파일(`r50-build-round-fingerprints.txt`)로 두었다. 지문에는 라운드의 경험치·골드·적 수·체력·접촉·속도 계약과 보스의 HP·처치 골드·문턱·지원 적 수치가 들어가므로, 다음 단계에서 R41–R50 값이나 보스 계약이 바뀌면 시험이 실패한다. 앞 40개는 R40 빌드 고정 파일과 같다.
- 여호수아 R37–R40 라운드 ID(`joshua_01`–`joshua_04`)와 속도 계약은 바뀌지 않았다. 여호수아 끝을 R42로 옮겨도 R37–R40 지문은 같다.
- R42·R45·R48 보스 기록은 R21 이후 순서가 검증되는 목록에 이어 붙인다. R50 완료 시점의 목록은 R21부터 R48까지 세 라운드 간격 10개이며 앞선 일곱 기록은 R40 빌드 저장의 내용 그대로다.
- R51 이상 체크포인트, 아직 설치되지 않은 보스 라운드(R51)의 보스 기록, 라운드와 맞지 않는 새 보상 정책, 알 수 없는 미래 보상을 담은 저장은 "새 버전 필요"로 거절하며 원본과 백업을 바꾸지 않는다.
- 설치된 보스 라운드 기록의 개수·순서 손상은 R40과 같이 손상 복구(백업 읽기) 경로를 탄다. 이번 단계에서 바꾸지 않았다.
- 여호수아까지만 설치된 구성은 R42 완료 화면에서 사사기 시작을 제안하지 않고 새 도전만 제안하며, 사사기로 넘어간 저장은 "새 버전 필요"로 읽기를 거절한다.
- 책 완료 화면의 다음 장, 제목, 설명, 시작 버튼 문구는 `AdamRoundPresentation`의 Host 기반 함수가 계산하고 게임 화면은 그 결과를 그린다. R50 Host 시험은 같은 함수로 여호수아까지만 설치한 구성, 전체 설치 구성, R50 완료를 확인한다.

## 검증 범위

- Core 시험 전체(R50 추가 5개 포함 228개)가 통과했다. R40 빌드가 만든 완료 저장을 바이트 그대로 읽은 뒤 R41로 이어 가고, 사사기 진입의 쓰기 실패·재시도·중복 커밋, 보스 기록 순서, 미래 저장 보존을 확인했다. R40 시험의 "설치 끝 다음 라운드는 미래 저장" 단정은 R51·R52로 옮겼다.
- Core에서 R16–R50 연속 좌표 전투를 완료하고 R42·R45·R48의 실제 처치와 예고·투사체 시점 저장 재개를 확인했다(`--r50-series sling 7`). 고정 테스트 장비와 체력을 사용했으므로 일반 난이도 밸런스는 미검증이다.
- 격리 사본 변이 6개를 모두 검출했다. 보스 기록이 R40 뒤로 이어지지 않는 옛 구조, 사사기 진입을 일반 다음 라운드로 건너뛰는 경로, 여호수아 완료 전 사사기 진입, 여호수아 완료를 옛 설치 끝(R40 기준 상수) 기준으로 판정하는 구조, 새 보상 정책 미등록, R41·R42를 사사기로 넘기는 책 경계다. 이 중 보스 기록 변이는 저장 수명 검증이, 여호수아 완료 전 사사기 진입 변이는 R40 저장 이어 하기 시험의 후보 저장 검증("새 버전 필요" 판정)이, 정책 미등록 변이는 새 저장 읽기 거절이 먼저 막아 검출됐다.
- PR 리뷰 반영(1회차)에서 변이 4개를 더 검출했다. Core 변이 2개(R42 보스 HP 54,500→54,000, 사사기 속도 계약 jd1 0.69→0.70)는 다른 시험이 단정하지 않는 값이라 R50 지문 고정 시험만 실패했다. Unity 변이 2개(다음 장 계산에서 사사기 설치 조건 제거, 완료 설명에 사사기 대신 여호수아 설치 여부 전달)는 사사기 진입 재시도 Host 시험이 잡았다.
- Unity EditMode 전체 433개와 라운드 진행 PlayMode 14개(R10–R50 Enter 경계 포함)가 통과했다. 첫 EditMode 실행에서 책 머리띠 시험이 여호수아 총 라운드를 4로 기대해 3건 실패했고, 6으로 고치고 R42·사사기 경우를 더했다.
- 격리한 macOS 앱에서 이전 빌드 QA 앱이 직접 만든 R40 완료 저장으로 시작했다. 저장 파일을 바꾸지 않고 읽은 뒤 Enter로 R41에 들어갔고, R42 완료 화면에서 사사기 시작(Enter)으로 R43에 들어가 R50을 완료했다. 두 진입 모두 도전 ID와 골드가 유지됐다. 전투는 자동 입력과 테스트용 장비·체력으로 진행했다. R42·R45·R48에서 세 방향 예고 상태와 실제 적 발사체를 확인했다. 투사체 캡처에는 HUD의 보스 이름·파편 3방향 문구가 보이지만 보스와 투사체는 화면 밖에 있다(R40과 같은 구도). R50 완료 시점에 보스 기록은 R21–R48 순서였고 앞선 일곱 기록은 시드 저장과 같았다. 새 프로세스에서 R50 완료를 복원했고 사사기·여호수아·R51 진입을 제안하지 않았으며, 완료 화면에서 Enter를 두 번 누르고 일시정지를 풀어도 저장 파일이 바뀌지 않았다. 완료 화면 문구는 캡처 글자 인식으로 확인했다(여호수아 완료·사사기 시작, 사사기 8 완료·1–8 라운드 클리어).
- 자연 플레이의 난이도 밸런스, 모바일 기기와 성능은 미검증이다.
