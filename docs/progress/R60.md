# 사사기 R51, 룻기 R52–R54, 사무엘상 R55–R60

이전 버전의 R50 삼손과 사자 완료 저장은 그대로 읽힌다. R50 완료 화면에서 다음 라운드로 진행하면 사사기 R51을 이어 하고, R51 보스를 끝낸 뒤 룻기 시작을 명시적으로 선택하면 R52를 진행한다. R54 보스를 끝낸 뒤 사무엘상 시작을 명시적으로 선택하면 R55를 진행한다. 두 책 진입 모두 저장에 실패하거나 결과를 확인하지 못하면 완료 화면과 기존 저장을 유지하며 같은 operation으로 다시 시도한다. 진입 시 기존 도전 ID, 골드, 성장, 장비와 보상 기록을 승계한다. R60 엘라 골짜기의 보스를 끝내면 완료를 저장하며, 다음 체크포인트 번호 61에는 진입할 수 없다.

## 결정 기록 (초기 수치)

모두 개발 초기 수치이며 자연 플레이 밸런스로 확정한 값이 아니다. 2026-11-20 이슈 #7에서 R50 방식을 따르는 추천안으로 정했다.

- 책 배분: 사사기를 계획대로 R51(보스)에서 끝내고, 정경 순서대로 룻기 3라운드와 사무엘상 6라운드를 두었다. 책 길이가 3의 배수이고 보스로 끝나는 흐름, R21부터 세 라운드마다 보스인 흐름을 따랐다. 짧은 룻기(4장)는 최소 단위인 3라운드로, 사무엘상은 신명기·여호수아와 같은 6라운드로 두어 R60에서 책과 설치 범위가 함께 끝난다.
- 라운드 수치: 민수기 공식을 전역 오프셋 `o = 라운드 − 22`로 계속 연장했다. 경험치 7200+200o, 완료 골드 420+20o, 적 생성 1560+60o, 체력 440+20o / 295+14o / 1070+35o, 3라운드 단위로 빠른 적 비율을 교대한다. 접촉 피해는 책마다 1씩 올려 룻기 19/18/23, 사무엘상 20/19/24다. 속도는 책마다 0.02(무거운 적 0.01)씩 빨라진다.

- 적과 아트: 룻기 `rt1–rt3`와 사무엘상 `sm1–sm3`는 새 창작 생물 ID이며, 새 아트를 만들지 않고 기존에 검수한 출애굽기 R06 스프라이트(ex17·ex16·ex18)와 보스 스프라이트(defilement_weaver)를 재사용했다. 룻기 지형은 밀빛, 사무엘상 지형은 푸른 회색 색조로 구분했다. 전용 아트는 Claude Design 담당의 후속 작업이다.

## 저장과 기록

- 기존 R01–R50 지문과 과거 보상 필드를 그대로 유지한다. R50 빌드에서 고정한 R01–R50 지문 파일과 새 빌드의 지문이 같고, R50 빌드의 QA 앱이 직접 만든 R50 완료 저장을 고정 파일(`r50-build-complete-save.json`, 바이트 사본)로 두고 새 빌드로 읽는다.
- 이 빌드의 R01–R60 지문 60개를 고정 파일(`r60-build-round-fingerprints.txt`)로 두었다. 앞 50줄은 R50 빌드 고정 파일과 같다. 다음 단계에서 R51–R60 값이나 보스 계약이 바뀌면 시험이 실패한다.
- 사사기 라운드 ID와 범위를 설치 끝 상수 대신 책 끝 상수(`JudgesContent.LastRound = 51`)로 옮겼다. R43–R50의 ID(`judges_01`–`judges_08`)와 지문은 바뀌지 않았다.
- R51·R54·R57 보스 기록은 R21 이후 순서가 검증되는 목록에 이어 붙인다. R60은 보스 라운드이지만 다음 라운드가 시작되지 않으므로 완료 기록이 `Run.Boss`에 남는다(R30 설치 끝과 같은 방식). R60 완료 시점의 목록은 R21부터 R57까지 세 라운드 간격 13개이며 앞선 열 기록은 R50 빌드 저장의 내용 그대로다.
- R61 이상 체크포인트, 설치되지 않은 보스 라운드(R63)의 보스 기록, 라운드와 맞지 않는 보상 정책(목록과 `Run.Boss` 모두), 알 수 없는 미래 보상을 담은 저장은 "새 버전 필요"로 거절하며 원본과 백업을 바꾸지 않는다.
- 사사기까지만 설치한 구성은 R51 완료 화면에서 룻기 시작을 제안하지 않고 새 도전만 제안하며, 룻기로 넘어간 저장은 "새 버전 필요"로 읽기를 거절한다. 룻기까지만 설치한 구성도 R54에서 같다.
- 책 완료 화면의 다음 장, 제목, 설명, 시작 버튼 문구는 R50 단계에서 옮긴 `AdamRoundPresentation`의 Host 기반 함수가 계산한다. R60 Host 시험은 부분 설치 두 구성, 전체 설치 구성, R60 완료를 이 함수로 확인한다.
- R50 시험의 "R50 완료 = 설치 끝" 단정(완료 문구 '사사기 8 완료', R51 미설치)은 R50이 일반 라운드가 되었으므로 "R50 뒤 R51 진행"으로 바꾸고, 완료 단정은 R60 시험으로 옮겼다. 이전 단계 시험의 "설치 끝 다음 라운드는 미래 저장" 단정은 R61·R62로 옮겼다.

## 검증 범위

- Core 시험 전체 232개(R60 추가 4개 포함)가 통과했다. R50 빌드가 만든 완료 저장을 바이트 그대로 읽은 뒤 R51로 이어 가고, 룻기·사무엘상 진입의 쓰기 실패·재시도·중복 커밋, 보스 기록 순서, 미래 저장 보존을 확인했다.
- Core에서 R16–R60 연속 좌표 전투를 완료하고 R51·R54·R57·R60의 실제 처치와 예고·투사체를 확인했다(`--r60-series sling 7`, `next_round` 61). 고정 테스트 장비와 체력(10,000)을 사용했으므로 일반 난이도 밸런스는 미검증이다. 이 고정 장비 실행에서 라운드당 처치 수는 R16 1,132에서 R59 127, R60 46(보스 라운드)까지 줄었다.
- 격리 clone에서 Core 변이 9개를 모두 검출했다. 룻기·사무엘상 진입을 일반 다음 라운드로 건너뛰는 경로 두 개, 사사기를 설치 끝 기준으로 완료 판정하는 구조, 새 보상 정책 미등록, 룻기 접촉 수치를 사사기에서 복사, R60 보스 HP 변경, 사사기 범위를 설치 끝 상수로 두는 옛 구조다. 룻기·사무엘상을 앞 책 완료 전에 진입하는 변이 두 개는 R50 저장 이어 하기 시험의 후보 저장 검증("새 버전 필요")이 먼저 막아 검출됐다. R60 보스 HP 변이는 R60 지문 고정 시험만 잡았다. 변이 정의는 `evidence/r60/mutations.tsv`(로컬 증거)에 있다.
- Unity 격리 사본에서 변이 4개를 모두 검출했다. 다음 장 계산에서 룻기 설치 조건 제거, 완료 설명에 룻기 대신 사사기 설치 여부 전달, R51 완료 뒤를 일반 다음 라운드 대기로 처리하는 변이는 룻기 진입 재시도 Host 시험이, 사사기 총 라운드를 설치 끝 기준으로 계산하는 변이는 책 머리띠 시험과 제목 시험(14건)이 잡았다.
- Unity EditMode 전체 464개와 라운드 진행 PlayMode 14개(R10–R60 Enter 경계 포함)가 통과했다. 첫 EditMode 실행에서 R15 시험의 'R51 정산 단계 체크포인트는 미래 저장' 단정 1건이 실패했다. R51이 이제 보스 라운드라 정산 단계가 다른 예외로 거절됐고, R61·R62로 옮겼다.
- 격리한 macOS 앱에서 이전 빌드 QA 앱이 직접 만든 R50 완료 저장으로 시작했다. 저장 파일을 바꾸지 않고 읽은 뒤 Enter로 R51에 들어갔고, R51 완료 화면에서 룻기 시작(Enter)으로 R52, R54 완료 화면에서 사무엘상 시작(Enter)으로 R55에 들어가 R60을 완료했다. 세 진입 모두 도전 ID와 골드가 유지됐다. 전투는 자동 입력으로 진행했다. R51·R54·R57·R60에서 세 방향 예고 상태와 실제 적 발사체를 확인했다. R60 완료 시점에 보스 기록은 R21–R57 순서였고 앞선 열 기록은 시드 저장과 같았으며 R60 완료 기록은 `Run.Boss`에 있었다. 새 프로세스에서 R60 완료를 복원했고 룻기·사무엘상·R61 진입을 제안하지 않았으며, 완료 화면에서 Enter를 두 번 누르고 일시정지를 풀어도 저장 파일이 바뀌지 않았다. 완료 화면 문구는 캡처를 직접 보고 확인했다(사사기 완료·룻기 시작 버튼·완료 골드 +1000, 사무엘상 6 완료·1–6 라운드 클리어·완료 골드 +1180).
- 자연 플레이의 난이도 밸런스, 모바일 기기와 성능은 미검증이다.

## 다음 단계에서 할 일

- R60 완료 저장 고정 파일은 아직 없다. 다음 단계는 R60 QA 앱이 만든 완료 저장(로컬 증거 `evidence/r60/player/round-save.json`)을 고정 파일로 옮겨 R61 이어 하기를 확인한다. R60은 보스 라운드이므로 다음 라운드 진입 때 `Run.Boss`의 R60 기록이 보스 기록 목록으로 옮겨지는지도 함께 확인한다.
- 사무엘상의 끝(`FirstSamuelContent.LastRound`)과 설치 끝이 같은 60이다. R61 이후에 사무엘하를 붙이려면 R60 완료가 책 완료(`FirstSamuelComplete`)로 바뀌어야 하므로, R30→R31 신명기 진입과 같은 명시 진입 경로를 추가한다.
