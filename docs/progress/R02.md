## 구현된 동작

- 새 도전은 R01만 시작한다. R01 완료 후 남은 선택을 처리한 세션에서 `StartNextRound(r02)`가 새 세션을 반환한다. 진행 중·사망·미처리 선택·다른 번호·중복 전환을 거절한다.
- R02는 실제 catalog의 `genesis_02`, B1/B2/B3, 360마리, rawXP600, 동시50, 일반180초/생성마감170초, 완료35골드를 소비한다. 완료 보상/해금은 definition에 읽은 catalog 값을 사용한다.
- R01/R02 완료 시 현재 최대 체력으로 회복하고 완료골드/해금을 한 번 지급한다. 5킬당1골드의 remainder·레벨·잔여XP·무기/보조·도전 시작의 영구 강화 스냅샷·잔액·해금은 유지한다. R02 진입은 추가 회복/보상을 하지 않는다.
- 새 아레나에서 적/드롭/발사체/위치/공격 시계와 마지막 피격 시계를 초기화한다. 이전 session의 진행·선택·Capture와 이전 World.Advance는 새 라운드에 영향을 주지 않는다. 호출자는 반환된 session으로 새 World를 만든다.
- R02 완료 후 `RoundNumber=3, Stage=between_rounds, Wave=null`로 저장한다. 남은 선택도 여기서 복원한다. R03 진입/보스 구현은 없다. 사망하면 run을 비우며 새 도전은 R01 레벨1부터 시작하고 영구 정보는 유지한다.
- `wilderness_voice`와 `lightning`은 영구 해금만 구현했다. 장착/공격/선택 풀은 기존 `bible`, `jawbone`, `sling`뿐이다. 후속 무기 코어·무기10종·스킬420종 구현은 후속 단계다.

## 저장·호환 경계

GameSnapshot schema1을 유지하면서 optional `Run.RoundFingerprint`를 추가했다. 신규 fingerprint는 라운드 ID·전체 웨이브/적 수치·예산·상한·보상·해금을 포함한다. 달라진 정의로 Resume하면 거절하고 파일을 보존한다. 대기 체크포인트 Resume에는 **마지막 완료 라운드**의 정의를 전달한다.

fingerprint 없는 legacy는 R01 진행 및 R01 완료→R02 대기만 허용한다. Capture/전환 때 보강하고 R02 진행/R03 대기에는 필수로 요구한다. legacy R01은 필드가 없던 미래 웨이브 변경까지 탐지하지 못하므로 원본 R01 catalog를 유지해야 한다. World 없는 저장을 읽을 수 있지만 좌표 복원으로 보고하지 않는다. 구 실행기의 R02 재개/downgrade 호환은 제공하지 않는다. 미래 schema 거절·손상 백업 복구·null 원소·World 시계/ID 정합 회귀는 유지한다.

전환은 `SaveStore.Transact(revision, operationId, change)` 내부에서 실행한다. 쓰기 실패 시 디스크의 완료 체크포인트가 남고 같은 명령으로 재시도할 수 있다. 결과를 모르면 같은 operation ID로 재조회/재시도하며 보상/전환을 다시 실행하지 않는다. 중단/뒤로는 저장된 완료 체크포인트를 보존한다. 실제 UI 연결은 별도다.
