# R01 아담 — 선행 코어

상태: 순수 C# 구현·로컬 검사·독립 코드 리뷰·GC를 완료하고 작업 브랜치로 공유하는 단계다. Unity 게임 라운드 완료가 아니다.

## 구현한 범위

- 3분 시간표, 유한 생성 예산 240, 동시 40 상한, 생성 지연/마감, 전멸과 순간 빈 화면의 구분.
- 처치·별도 경험치 드롭/회수, 레벨별 요구량과 20/40레벨 배율, 순차 선택·일시정지·선택 후보 저장.
- 시작 무기 3종의 8레벨 수치·공격 시계·연사·관통/동일 대상 피격 기록·전방 부채꼴 판정 프리미티브.
- 보조 10종의 선택/단계 및 공격·이동·획득·방어·경험치·반격 수치 연결 API. 실제 VFX/이동/물리는 미구현.
- 라운드 종료 회복·성장 유지·다음 라운드 대기, 사망 시 도전 초기화·영구 재화/구매/해금 유지.
- 공통 영구 강화 8종의 구매/선행 조건/무료 전체 환불·새 도전 스냅샷 적용. 무기별 영구 노드는 미구현.
- 스키마 1 저장, revision/operation ID, 임시 파일 검증/flush/원자적 교체, 백업 복구·미래 버전 거절, 실패·재시도 경계.
- 창세기 9라운드/27종/27웨이브/3보스의 검증된 데이터. R02~R09의 전투 구현은 아직 하지 않았다.

## 검증 결과

| 검사 | 상태 | 범위 |
|---|---|---|
| netstandard2.1/C#9 컴파일 및 코어 시험 | PASS | 실제 .NET SDK 실행, 45개 시험 |
| 콘텐츠 무결성 | PASS | 6,210 생성 예산 / 원시 XP 18,600 / 전부 처치 기준 기본 골드 2,667 |
| 실제 콘텐츠 변이 | PASS | 손상/중복/수치/상한/분포/보스/해금/진화 등 16건과 보조 ID 회귀 검출 |
| 원 회귀의 코드 변이 | PASS | XP 보너스·돌 상한·잘못된 조기 종료·NaN 복원·피해 처치 누락·완료 후 선택 복구·stale revision 덮어쓰기 7건을 격리 사본에서 재현하여 실제 시험 실패 확인 |
| 시작 무기별 규칙 시뮬레이션 | PASS | 각 240 처치 주입 / 원시 XP 300 / 레벨 8 / 골드 73 / 다음 라운드 체크포인트·저장 복원 |
| 독립 코드 리뷰 | PASS | HIGH 2/MEDIUM 2 발견 후 수정·후속 독립 검토에서 해결 확인. 환불/검사·CI의 최종 추가 검토도 완료. 증거 경로의 재실행 덮어쓰기는 고유 경로로 수정 |

| 실제 Unity 컴파일/플레이·UI/UX·성능 | NOT_RUN | 사용자 요청으로 Unity 설치 연기 |
| Android/iOS 빌드·실기기 | NOT_RUN | 프로젝트·기기 검증 대기 |
| GitHub Actions | 정의 추가 | 로컬 PASS와 원격 CI 결과는 구분. 실제 run 상태는 GitHub에서 확인 |

시뮬레이션은 적을 실제 무기로 싸워 처치하지 않고 처치를 주입한다. 따라서 DPS·생존 난이도·타격감·게임 밸런스를 검증한 것이 아니다. 시작 무기별 결과가 같다는 것은 전투 성능이 같다는 뜻이 아니다.

다음 단계는 승인된 Unity 프로젝트에 이 코어를 연결해 입력·이동·타깃·충돌·공격 시계 저장·선택 화면과 실제 아담 전투를 구현하는 것이다. 모바일 수용 조건 전에는 후속 라운드의 전투 범위를 확장하지 않는다. 현재 다음 라운드 대기 체크포인트는 복원 가능하지만 R02 플레이는 시작하지 않는다.
