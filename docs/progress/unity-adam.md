## Local checkpoint policy and recovery

Original `game-design.md` §§179–199 specifies completion/death/permanent progress and leaves mid-battle snapshots separate; `mobile-platform-plan.md` §§17–21 leaves the detailed cadence undecided. The approved worker packet extends this prototype with a local checkpoint every **5 simulated combat seconds**, plus immediate start, level-up modal entry/selection, completion, death, pause and focus/app loss saves. The timer is checked after a host tick capped at0.1 seconds, so the checkpoint interval/maximum rollback during an interrupted write is at most **5.1 simulated seconds** rather than a strict sub-five-second guarantee; a failed save freezes progress and is visibly reported. This is a prototype-specific extension, not a change to later content or mobile durability guarantees.

Session capture and world capture occur on the same main-thread boundary. Terminal checkpoints omit the obsolete world. `SaveStore.Commit` performs the existing atomic validated replacement and revision/operation-ID checks. The host freezes the payload, expected revision and operation ID on failure; Retry repeats the same operation, while Reload explicitly discards uncommitted progress and loads the last valid primary/backup. Future-version/corrupt-unrecoverable saves stop input and preserve the original. No automatic overwrite or auto-retry loop hides uncertainty. Normal quit attempts a checkpoint; OS termination can still roll back to the last checkpoint. A successfully committed death removes the run and retains gold/unlocks. Disk durability during actual power loss and mobile OS kill remains untested.

Save path: `Application.persistentDataPath/adam-prototype.json`. The template bundle identifier is still `com.DefaultCompany.2D-URP`; company/product are `BibleSurvivor` / `Adam Prototype`. The machine-specific resolved path is retained only in ignored evidence. A production identifier/migration is a later packaging decision. Tests use disposable temporary directories; the explicit Player GUI smoke created its own local game checkpoint. The ordinary player save is separate from existing CLI saves.
