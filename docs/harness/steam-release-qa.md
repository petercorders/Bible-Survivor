## 릴리스 순서

1. **출시 범위 확정.** 구약 R01–R180을 기준으로 영구 성장, 추가 무기, 지원 OS·언어·입력, 정식 출시 또는 Early Access를 확정한다. #44를 검토하고 통합 후보를 만들며 버그 수정과 새 기능의 합류 기준을 정한다.
2. **저장과 플레이 흐름 검증.** 진행 손실·설치 실패·크래시·보상 중복에 재현이 있으면 후보를 보류한다. 첫 플레이어의 R01 시작과 R09 이어 가기를 관찰하고, 후기 대표 저장과 실제 전체 완주를 별도로 확인한다. 결함마다 재현·수정 SHA·재검사 로그를 기록한다.
3. **출시 후보 고정.** 운영 빌드에 커밋·빌드 버전·Steam Build ID를 연결한다. Steam 비공개 테스트 분기에서 새 설치·오프라인 실행·업데이트·저장 복구·대표 진행을 확인한다. 지원하지 않는 OS 입력과 Steam 기능은 상점 표시를 검수할 때 제외한다.
4. **상점과 빌드 심사.** 범위와 제품명이 정해지면 상점 준비를 플레이 QA와 병행한다. 실제 빌드의 스크린샷·트레일러, 지원 기능과 최소 사양, 적용할 가격을 확인하고 상점부터 제출한다. 공개 전 Coming Soon 기간은 최소 2주며 Valve는 상점 심사에 7영업일 이상 여유를 권장한다. 빌드 심사 전에 기본 브랜치, Developer Comp와 상점 패키지의 depot, 실행 옵션을 대조한다. 최근 빌드를 Steam의 플레이 버튼으로 5분 이상 실행하고, 심사용 대표 후기 저장과 접근 안내를 제공한다. 계정과 앱의 준비 상태는 Steamworks 대시보드에서 확인한다. [Valve 심사 기준](https://partner.steamgames.com/doc/store/Review_Process) · [Coming Soon](https://partner.steamgames.com/doc/store/coming_soon)
5. **출시 승인과 출시 직후.** 심사 통과와 미해결 출시 차단 0건을 확인한 뒤 승인된 빌드를 공개한다. 직전 정상 빌드와 호환 저장을 보관한다. 공개 직후 Steam에서 새로 설치해 첫 플레이와 저장 재실행을 확인하고, 크래시·실행 실패·저장 손실 보고를 우선 추적한다. [Valve 출시 절차](https://partner.steamgames.com/doc/store/releasing)
