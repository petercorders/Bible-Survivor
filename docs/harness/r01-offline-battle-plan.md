# R01 좌표 전투 구현 계획

승인: 사용자가 Unity 없이 가능한 코드를 계속 진행하라고 재차 명시했다. 현재 아담 코어의 이동·타깃·자동공격·명중·처치·경험치 흡수를 연결하는 동일 R01 범위다. 그래픽 생산/QA는 별도로 계속 진행하며 이 작업의 선행 조건이 아니다.

## 단계와 소유

1. 전투 담당은 `BattleWorld.cs`와 `BattleWorldTests.cs`를 맡는다. 고정 60Hz, 단위 벡터 이동/마지막 방향, 화면 밖 결정적 생성, 몬스터별 속도·접근, 성경 공전·턱뼈 부채꼴·물맷돌 투사체/관통·거리 회수·접촉 피해를 기존 AdamSession에 연결한다. 근접 공격의 피해는 Session.Hit 경로만 사용하며 Kill 호출로 전투를 대체하지 않는다.
2. 통합 담당은 CLI, catalog 속도 입력, 저장 DTO의 선택적 World 상태, 테스트/CI 진입점과 문서를 맡는다. 플레이어 입력과 외부 선택을 제공하는 host 역할이다. 단순 처치 주입 시뮬레이션은 기존 회귀 기준으로 유지하되 새 좌표 전투 결과와 명확히 분리한다.
3. 독립 코드 리뷰에서 실제 공격/처치/드롭의 경로·투사체 스윕/중복 방지·상한·사망/종료 순서·일시정지와 선택 중 시간 정지·분할 시간의 결정성·스냅샷 왕복을 확인한다. 지적은 수정·재검증하고 원 회귀를 변이 시험으로 검출한다.
4. R01의 추가 GC 기록 후 같은 작업 브랜치로 커밋·push하고 원격 SHA/CI를 확인한다. merge/배포는 하지 않는다.

## 수용 조건

- 세 무기 각각 적에게 실제 좌표 판정으로 피해를 주고, 죽은 위치에 경험치가 생겨 가까워졌을 때 회수된다. 먼 곳의 적을 직접 죽이거나 XP를 바로 지급하지 않는다.
- 전투 튜닝은 월드 단위의 초기값으로 명시한다. 기존 피해·주기·웨이브 수치를 바꾸지 않고 조작감·Unity 물리·성능 실측으로 확대하지 않는다.
- 보유 장비·보조가 바뀔 때 프로필이 반영되지만 매 프레임 공격 타이머를 초기화하지 않는다. 탄 수·생성 수·참조 상태에 상한을 둔다.
- 같은 시드/동일 시간별 입력은 같은 결과를 만들고, 호출 간 프레임 분할만 바꿔도 동일 고정 step 결과다. 일시정지/레벨업 선택 동안 좌표·타이머·수명·회수·피해가 멈춘다.
- 중간 저장은 좌표·난수·고정 step 나머지·공격/투사체/히트 기록·드롭 상태를 포함한다. 복원 후 같은 입력으로 진행하면 무저장 실행과 같아야 한다. 잘못된 좌표·미래 적 ID·상한 초과·세션 시간 불일치를 거절한다.
- CLI는 시드/입력 정책과 실제 발사/명중/처치/수집/피해 결과를 내고, 사망/정상 종료를 구분한다. 플레이어의 승리나 특정 처치 수를 보장하지 않는다.
- 실제 Unity/화면/기기/아트 적용은 NOT_RUN이다. 그래픽이 아직 준비 중이라는 이유로 이 독립 코드 작업을 멈추지 않는다.

## 모델·재시도

순수 전투 구현은 별도 상속 모델 담당, 통합·저장은 현재 담당, 리뷰는 독립 세션을 사용한다. 모델 ID/usage가 제공되지 않으면 미측정이다. 기능별 수정 1회 후 반복 실패면 원인/검증을 재평가하고 같은 명령을 무한 반복하지 않는다. 환경 부재를 고성능 모델 재시도로 해결된 것으로 기록하지 않는다.
