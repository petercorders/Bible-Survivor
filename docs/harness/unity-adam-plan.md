# Unity 아담 시제품 연결 계획

상태: 2026-11-14 사용자 “너가 진행해줘”로 이 구체 계획 승인. 프로젝트 생성과 연결을 진행한다. 기존 순수 C#·그래픽 작업 승인은 유지한다.

## 범위와 소유

- 기존 저장소 내부 `UnityGame/`에 설치된 Unity 6000.6.9f1의 2D 템플릿으로 프로젝트를 만든다. 홈이나 별도 저장소를 초기화하지 않는다. 계정·라이선스 변경은 포함하지 않는다.
- coordinator가 지정한 Unity 담당이 UnityGame의 씬·프리팹·어댑터를 단독 소유한다. R02 worker의 src/tests/tools는 수정하지 않는다. R02 인계 후 API와 리비전을 고정해 연결한다.
- 기존 Core를 로컬 UPM 패키지로 참조하는 방식을 우선 검증한다. 별도 유지보수 사본을 만들지 않는다. Core의 noEngineReferences asmdef, Unity 어댑터 asmdef, Editor·시험 asmdef를 분리한다. 프로젝트/패키지 연결 변경은 R02 담당 인계 이후 한다.
- 아담 한 라운드와 기존 세 무기 선택, 이동·자동 공격·적·XP·레벨업 최대 세 선택·HUD·일시정지·사망·완료만 화면에 연결한다. 후속 라운드와 보스는 이 Unity 시제품 범위에 추가하지 않는다.
- 그래픽 03은 독립 QA 통과 후 임포트한다. 그전에는 명시적인 임시 도형으로 실행 가능성을 검증한다. 최종 그래픽 완료로 기록하지 않는다.

## 동작과 복구

- 기존 고정 시간 간격 BattleWorld를 전투의 원본으로 유지하고 Unity는 입력과 표현을 담당한다. 키보드와 화면 터치 입력은 같은 이동 벡터로 변환한다. 화면 방향은 아직 고정하지 않는다.
- 선택/일시정지/앱 비활성 중 전투 시간을 멈추고 복귀 시 시간 누적과 입력을 초기화한다. 모바일 실기기 지원 완료로 보지 않는다.
- 전투 저장은 session과 world를 동일 시점에 캡처한다. 레벨 선택·완료·사망은 기존 SaveStore 트랜잭션으로 기록하며, 저장 실패 시 진행을 멈추고 재시도/재로드를 제공한다. 결과 불명 시 디스크를 다시 읽고 같은 operation ID로 확인한다. 취소는 마지막 유효 저장을 보존한다.
- 전투 자동 저장의 주기와 강제 종료 시 최대 롤백 범위는 구현 전에 기존 결정 문서와 대조한다. 미결정이면 별도로 제안하며 임의 정책을 완료 상태로 넣지 않는다.

## 수용 조건과 인계

1. Editor 실제 실행으로 라이선스 인식·패키지 해석·C# 컴파일을 확인한다. .ulf 파일의 유무만으로 라이선스를 단정하지 않는다. 실행 차단 시 오류와 해당 게이트만 기록한다.
2. Force Text·Visible Meta Files·GUID·asmdef 경계를 확인한다. Library/Temp/Logs/빌드/개인 로그는 커밋에서 제외한다.
3. 실제 EditMode/PlayMode로 입력 전달, 정지, 선택, 피해/사망/완료, 저장 재개와 중복 보상을 검증한다. 종료 코드와 새 NUnit XML을 보존한다. 순수 코어 시험과 구분한다.
4. 실제 화면과 입력을 독립 UI/UX 리뷰하고 높은 결함은 수정·재검토한다. UI 검증 전에 ui-ux 하네스 지침을 읽는다.
5. 기존 코어 회귀와 관련 변이, Unity 검사, 독립 리뷰 후 R01 Unity 연결 GC를 기록하고 승인된 작업 브랜치에 커밋·push·원격 CI 확인한다. merge/배포는 하지 않는다.
6. PC 플레이와 모바일/기기/성능 상태를 각각 기록한다. 실기기 미실행과 성능 미측정은 NOT_RUN으로 남긴다.

## 현재 근거

계획 작성 당시인 2026-11-13 설치 경로에서 6000.6.9f1 Editor 실행 파일을 확인했고 프로젝트/실행 검사는 아직 없었다. 2026-11-14 사용자 승인 후 프로젝트 생성·실제 컴파일/시험/빌드와 독립 리뷰를 진행했다. 현재 상태·한계·증거는 `docs/progress/unity-adam.md`를 따른다.
