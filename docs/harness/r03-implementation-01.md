# R03 실행 배정 01 — 보스 Core와 시각 인계

2026-11-15. 기준 `d8a7802`는 R02 실제 아트·피격·schema2 통합과 두 CI를 통과했다. 사용자의 지속 개발·멀티에이전트·PC 리뷰·GC/업로드 승인으로 R03 구현을 시작한다. 기존 `r03-core-plan.md`의 상세 규칙을 따르며 아래는 실행 범위 고정이다.

## Core 단일 작성자

R02 대기→R03 normal→2초 보호 intro→보스 추적/고정 target 예고/slam→지원군1회→보스 처치→저장 가능한 reward 대기를 첫 slice로 구현한다. 일반 완료 시 조기 회복/완료 골드/해금 금지, 보스 고정100골드1회와 일반5킬 remainder 분리, 죽음 우선/단조 clock/중간 저장/미래 형식 보호를 포함한다. 정식 보상 선택/최초3진화·완료 정산·between4는 곧바로 이어갈 다음 slice이며 이 첫 slice를 R03 전체 완료로 표시하지 않는다. 보상 미구현을100골드로 대체하거나 후보를 버리지 않는다.

기존 원본 확정값은 유지한다. 미정 수치는 계획의 기술 초기값으로 고정한다: 보스 속도비0.30/반경0.60, intro 배치 플레이어(0,+3), slam 원 반경1.20·고정 target·예고 중 추적 정지, 최초 공격 boss elapsed6초/예고4.8초, 지원6개 반경1.5 등간격·기술XP0. 이는 검증용 tuning이며 플레이 밸런스 확정치가 아니다. version/fingerprint에 포함한다. 지원 XP0은 일반1100예산에 포함되지 않으며 정식 보상/밸런스 단계에서 재평가한다.

변경 범위: 순수 Core/관련 C# tests·Sim CatalogReader/전용 boss CLI·최소 검사 연결·진행/회고. Unity/DLL/provenance/기존 아트·사용자 저장/Editor는 변경하지 않는다. 기존 v1/v2 저장·R1/R2 fingerprint/행동 보호를 유지한다. 정식 새 Boss 필드를 SaveFormat 명시 shape와 함께 갱신하고 아직 지원하지 않는 미래 버전/콘텐츠는 원문 보존 거절한다.

## 좁은 검증

대표1무기로 normal→intro→boss→kill→reward 대기와 중간 저장/재개를 확인한다. intro보호/6초slam target고정·1회/50%지원1회·치명우선/180초 boss timeout없음/중복골드·미래저장 보호를 관련 단위 시험으로 검증한다. 원래 회귀 변이는 조기 Finish/180초 boss종료/지원flag누락/중복골드·clock복원 중 실제 구현 위험에 맞는 최소 핵심만 적용한다. 전체3무기×모든phase/seed/화면 조합·픽셀대조를 추가하지 않는다. 기존 검사는 마지막 source 고정 후 한 번 실행하고 변경 없으면 재실행하지 않는다. 순수 Core 독립 리뷰 뒤 DLL/Unity 연결은 별도 단일 작성자에게 인계한다.

## 병렬 시각 준비

지정 Claude Design 담당은 C1폭력의 그림자/C2목재 포식자/C3잔해 거인·네피림의 폭군과1.2초 공격 예고의 별도 인계 규격·아트를 준비한다. Core 소유 파일과 겹치지 않는 외부 폴더만 쓴다. 두 모델 아이디어 비교는 후보 근거이며 곤봉 실루엣+실제 판정 고정 경계의 초기 시안을 우선하되 성경 사건·게임 각색을 구분한다. 원격 Design 연결 여부와 픽셀 제작 방식을 사실대로 기록한다. 독립 검수 전 Unity 최종 임포트는 하지 않는다.

모델은 일반 구현 Sol 우선, 별도 Astra 호출 없음. 실제 토큰 기준점/결과·실패/수정 비용을 기록하고 비용·절감률이 미측정이면 그대로 둔다. 종료 게이트는 관련 검사→독립 리뷰→필요 수정→프로젝트 GC→선별 commit/push·해당 SHA CI다.
