# 저장 전환과 인수 조건

## 저장 계약

| 도메인 | 전환안 |
|---|---|
| 파일 | 읽기 지원 `SchemaVersion` 1/2/3/4, 신규 쓰기는 4. 로드는 저장 원본에 쓰지 않는다. 스키마 1은 현재 검증과 1→2 메모리 매핑을 먼저 수행한다. 스키마 2·3에는 기존 버전별 허용 필드·진행 검사를 그대로 적용한다. 첫 4 쓰기는 원래 포맷의 검증된 바이트를 보관한 후에만 진행한다. |
| 도전 | 기존 도전 `CombatRulesVersion=1`, 신규 도전 `CombatRulesVersion=2`. 도전 버전은 시작 후 종료까지 유지한다. 물리, 성장 후보, 진화 적격·보상 후보 검증을 동일한 버전에 연결한다. 새 도전은 별도 `PermanentCatalogVersion=1`과 시작 랭크 사본을 보유하고, 레거시 도전은 기존 사본만 유지한다. 출시 이후 기록된 도전 카탈로그의 효과·가격 영수증 버전은 보존하며 현재 카탈로그와 독립적으로 읽을 수 있어야 한다. |
| 진행 | 스키마 4의 `Run.CampaignLayout`을 `genesis` 또는 `campaign`으로 둔다. 유효한 기존 schema1/2는 `genesis`, schema3은 `campaign`. 새 R01은 `genesis`, R09→R10 책 진입 때 `campaign`. 신규 시작·책 진입·전투 저장이 스키마 4를 다시 2/3으로 낮추지 않는다. `SaveFormat.Probe`, `GameSnapshot.Validate`, `AdamSession`, `AdamCatalog.ForCheckpoint`의 스키마/라운드 판정을 같이 변경한다. |
| 월드 | v1 도전은 기존 encounter 기반 월드 1~5, 시각·전투 개체·연사 복원을 유지. v2 전투 월드가 있을 때 `World.SchemaVersion=6`으로 고정. 보스의 고유 직렬화 버전과 카탈로그 지문은 유지하고 월드 버전 판정만 도전 버전을 보게 한다. |
| 프로필 | `Gold:int64`, `Upgrades`, `PaidRanks`(노드 ID→구매 랭크 오름차순 골드 값 배열), `HighestSettledRound`(0~180), `EvolvedWeapons`(기본 ID의 고유 집합), 기존 `UnlockedWeapons`와 `OldTestamentClear`를 보관한다. 랭크·영구 선행·해금·진행·업적을 검증한다. 랭크별 영수증은 양의 정수이고 개수가 정확히 랭크와 일치해야 한다. 도전 사본은 저장된 도전 카탈로그와 랭크·선행 구조로 검증하고, 구매 잠금·영수증 검증을 현재 프로필 랭크에 다시 위임하지 않는다. 금액 계산은 checked int64. |
| 승인 영수증 | 마지막 프로필 명령의 `operationId, expectedRevision, requestDigest, resultingRevision, goldDelta`를 같은 후보에 기록한다. 해시는 정렬된 불변 요청 필드의 정규 양식에서 계산한다. 일반 자동 저장에도 직전 프로필 명령 영수증이 유지된다. ID는 `{expectedRevision}:{UUID}` 형식으로 고정한다. ID 안의 리비전과 요청 값이 다르면 거절한다. 영수증이 남아 있는 같은 ID는 다른 다이제스트를 거절하고, 이미 더 최신 명령으로 대체된 ID는 원래 리비전이 오래되어 다시 실행할 수 없다. |
| 보상 | 현재 및 완료 이력의 각 보상에 생성 당시 `RulesVersion`을 고정한다. 정산 이후에도 저장 시 캡처한 무기·보조·형태·해금·보상 ID로 그 버전의 후보를 다시 검증한다. 기존 `PolicyId`와 `EvolutionRules.Contract` 지문 입력은 유지한다. schema1/2의 레거시 R03 보상 승격 및 허용 지문 처리도 v1 정책을 사용한다. |

### 이전 확인과 보존

1. 1~3을 기존 구조로 검증한 다음 메모리상 전환한다. 구 공통 8종의 랭크를 복사하고, 랭크별 지불액은 기준 커밋의 고정 8개 가격표로 복원한다. 신규 랭크는 누락을 0으로 해석한다. 향후 가격 변경은 이미 기록된 영수증에 영향을 주지 않는다. 무기 해금과 현재 도전 사본은 승계하며, 신규 무기 풀을 기존 도전의 신규 선택에 섞지 않는다.
2. `HighestSettledRound`는 (a) 해금 기록에서 증명되는 최대 R01~R07, (b) 유효한 도전 커서가 있으면 Rnn−1, (c) 적용·완료된 보스 이력의 최대 라운드 중 최댓값으로 초기화한다. R180 보스 처치 기록만 있으면 R179까지 인정하고, 완료 정산은 저장 커서 181 또는 완료된 정산 증거가 있어야 R180으로 인정한다. 이미 도전이 없어 나머지 진행을 증명할 수 없는 계정은 확인 가능한 범위부터 새 정산으로 올린다. 기존 `OldTestamentClear` 시각과 ID는 보존한다.
3. 검증된 현재 `Run.Forms`와 적용된 진화 보상 이력에 있는 진화만 업적으로 복원한다. 증거가 없는 과거 진화는 이후 한 번 획득하면 열린다. 레거시 도전이 최초 전환 후 기존 무기를 진화해도 프로필 업적은 기록한다. 기존 무기 해금과 진화 업적은 전체 환불 이후에도 유지한다.
4. 첫 쓰기는 유효하게 읽은 실제 출처(주 파일 또는 백업)의 원본을 SHA-256과 함께 `.pre-skilltree-vN` 보관 세트에 두고, 기존 `.bak`가 있다면 별도 위치에 그대로 보관한다. 기존 schema1 백업 계약도 수행한다. 보관본이 이미 있으면 같은 원본 해시인지 확인하고 재사용하거나 경로에 해시를 포함해 독립 기록한다. 원본 보관이 실패하면 교체를 시작하지 않는다. 원자적 주 파일 교체·동기화와 주 파일 검증까지 완료해야 UI 성공이다.
5. 최신 빌드는 지원하는 버전의 손상과 신규 버전의 미지원 오류를 구분한다. 미래의 파일/도전/월드 버전과 알려지지 않은 계약 필드는 미지원으로 중단하고 정상 백업을 대신 읽어 진행하지 않는다. 전환 직후에 정상 schema4 주 파일과 정상 schema3 백업을 놓고, 기준 구 빌드가 UI 재시도까지 포함해 양쪽 바이트와 리비전을 보존하는지 확인한다. 구 빌드에서 주 파일이 없거나 손상되면 자체 복구로 구 백업을 선택할 수 있으므로 전환 저장을 구 빌드에서 복구하는 흐름은 지원 범위 밖으로 표시한다. 수동 다운그레이드는 구 파일을 별도 프로필에서 여는 승인된 복구에 한정한다.

### 전투 복원

- 기존 도전은 저장된 성장 후보 순서, 기존 규칙으로 계산한 고갈 보상, 보스 후보와 선택 영수증, 골드 정산, 연사와 무기 형태를 보존한다. 선택을 유효화할 때 현재 확장 카탈로그에서 다시 뽑지 않는다. 이후 레벨업·보스 생성도 기존 버전의 무기 풀을 사용한다.
- v2 성장 선택은 열릴 때 도전 버전·선택 시리얼·후보 ID 배열·후보 생성에 사용한 해금 무기 집합을 현재 장비와 함께 고정한다. 로드와 선택 시 같은 집합으로 재생성·대조하고, +25 고갈 보상도 그 스냅샷을 검사한다. R01/R02의 종료 보석 정산이 먼저 선택을 열고 뒤이어 무기를 해금해도 이미 표시한 선택에 소급하지 않는다. 다음 시리얼부터 해금 무기를 포함한다. 보스 선택이 장비를 바꿔 기존 대기 선택을 무효화하는 현재 경계에서만 보스 보상과 같은 커밋으로 해당 성장 선택을 새 장비 조건에 맞춰 재생성한다.
- 신규 도전은 공통·전용 랭크가 사본에 있어도 장착 후에만 해당 전용 효과를 계산한다. 런타임 상태는 정수 전투 틱·fractional remainder, 주기/타격/개체/선택 시리얼, 개체 위치·경로·초기 스탯·만료, 적중 ID·시각·연속 수, 표식·효과 종료·다음 실행 시각, 카운터 및 RNG, 마지막 피격·이동·회복 예산, 활성 예약의 부모/출처 태그를 포함한다. 거래를 불러올 때 이 값을 다시 만들지 않는다.
- 월드 검증에서 유일한 ID, 타임라인·개체 수·타격 예산 상한, 유한 값과 허용 상태, 무기와 형태의 일치, 적용되지 않은 보상 영수증/장비 관계를 확인한다. 적 사망 이후 남는 적중 ID는 상태 검증에 필요한 범위에서 유지하되 살아 있는 표적으로 다시 사용하지 않는다. 스키마와 배열의 행 수를 검증하고 현재 4MiB 저장 상한 내 최대 합법 상태를 직렬화·복원한다. 스키마 시작 단계에서 미래 버전을 진단하도록 검사한다.

## 구매와 전체 환불

| 단계 | 동작과 실패 처리 |
|---|---|
| 열기 | 일시정지에서 트리 진입 의사를 받으면 월드를 멈춘 상태에서 먼저 체크포인트를 저장한다. 실패 시 일시정지·기존 확정 리비전 유지. 동일 체크포인트 요청으로 재시도하거나 트리 진입을 취소한다. 이미 반영 여부를 모르면 아래 확정 절차로 돌아간다. 시작/사망/책 완료 화면은 그 상태의 확인된 커밋을 사용한다. |
| 구매 확인 | 요청에는 `operationId, expectedRevision, nodeId, displayedRank, displayedPrice`가 들어간다. 쓰기 잠금에서 최신 읽기 후 ID·리비전·현재 랭크와 다음 가격, 카탈로그·선행·라운드·해금·진화·충분한 잔액·최대 랭크를 확인한다. 검증된 복제본에서 한 단계 구매하고 지불액을 추가한다. |
| 전체 환불 확인 | 창을 열 때 실제 랭크와 영수증 목록의 정렬 다이제스트·합계·리비전을 고정한다. 확인은 동일 값을 요청에 담는다. 전부 일치할 때만 잔액을 실제 결제 합만큼 늘리고 모든 랭크와 영수증을 비운다. 수수료 0, 개별 환불 없음, 무기 해금·진화 업적·진행·도전 사본·보상·완주 유지. 목록이 비어 있거나 합계가 0이면 쓰지 않는다. |
| 직렬화와 저장 | Host 단일 쓰기 경로에서 성장·보상·새 도전·자동 저장·환불·구매를 직렬화한다. SaveStore의 파일 잠금, 리비전 비교, 스테이징 재읽기·동기화·원자 교체를 사용한다. Guard 통과 후 새 잔액·랭크·영수증·필요한 전환을 같은 커밋으로 쓴다. Storage의 동일 ID 처리 이전에 요청 다이제스트를 대조한다. 승인 화면과 Host는 확인된 주 파일의 리비전과 영수증을 읽고 한 번만 갱신한다. |
| 취소·뒤로 | 실행 전에는 해당 확인 화면 또는 트리를 닫으며 잔액·리비전·랭크를 변경하지 않는다. 트리 진입에서 이미 완료된 체크포인트는 유지한다. 확인을 시작한 뒤에는 끝까지 같은 요청을 보존하며 다른 변경·전투 재개·새 시작은 일시 비활성화한다. |
| 저장 전 실패 | 확정 잔액과 오류·재시도를 표시한다. 검증한 주 파일에서 기대 리비전과 기존 영수증을 확인하면 같은 요청과 후보로 재시도한다. 새 선택을 하려면 먼저 실패가 확정돼야 한다. |
| 교체 후 읽기 실패 | 성공/실패가 아직 확인되지 않았음을 표시한다. `Load`의 일반 백업 복구와 별개로 정상 주 파일만 확인한다. 같은 ID·다이제스트의 영수증이 있으면 이미 처리된 결과로 수렴한다. 주 파일을 읽을 수 없으면 재개와 쓰기를 계속 막고 동일 요청 확인을 지원한다. 기대 리비전이 여전히 맞으면 같은 후보로 다시 쓸 수 있다. 더 새로운 타 작업의 리비전이고 같은 영수증이 없다면 충돌로 읽기 전용 갱신 후 사용자에게 최신 금액·조건으로 재확인을 받는다. 요청을 새 ID로 자동 발행하지 않는다. |
| 재실행 | 다른 쓰기를 허용하기 전에 주 파일의 검증·영수증에서 확정 잔액을 복원한다. 커밋 전 강제 종료면 원래 잔액, 교체 뒤 강제 종료면 변경된 잔액과 영수증이 표시된다. 응답 여부를 추측해 차감이나 환불을 재전송하지 않는다. 주 파일이 손상된 경우 기존 복구 UI에서 복구 경로와 잔액을 보여준다. |

### R01~R180 회귀와 전투 실측

1. **콘텐츠** · 기준과 출시 후보에서 `r180-build-round-fingerprints.txt`의 R01~R180 지문 전체 대조. 라운드·웨이브·보스·클리어 및 골드 지급 정의 그대로. 보스 클리어 메시지·보상 선택·정산·보상 ID·완주 기록은 각 저장 전후 동일해야 한다.
2. **기존 무구매** · 기준 빌드와 변경 빌드의 레거시 규칙을 같은 `RunId`, 월드 시드, 60Hz 입력, 선택, 보상·완주 clock 입력으로 실행해 같은 단계의 전투 이벤트, 성장 후보와 선택, 골드 잔액, 무기 수량, 처치·피격, 보스 패턴·시간·도달 라운드를 비교한다. 기존 강화가 있는 세션과 저장에서 이어 시작한 레거시 세션도 각 기준 사본과 비교한다. 새 로그의 추가 필드를 무시한 공통 관찰 값이 일치해야 한다.
3. **새 무구매** · 신규 무기 풀과 새 합산의 무구매 결과를 별도 기준으로 수집한다. 세 시작 무기 × 고정 시드 7/19/41, 주무기 우선 및 획득 7종 우선 선택으로 R01부터 시작한다. R01/R02 첫 성장·골드·구매 가능 시점, R03 보스, R09→R10, R60, R160/R164 웨이브, R170→R171, R180 정산을 기록한다. 일곱 무기의 조건이 있는 통제 경로와 실제 이어진 자연 경로에서 적어도 한 번씩 해금→공격→진화→저장 복원→다음 도전 전용 효과를 검증한다. 초기 조건 미충족 시 다음 보스 창에서 계속 확인한다.
4. **새 투자** · 새 무구매와 동일 입력 정책을 사용해 60골드 첫 구매, 기초 8종 최대, 공통 공격/생존/탐색 각각 최대, 10종 전용 각각 집중, 치명·연사·투사체 및 방어·회복 혼합, R60/R180 fixture 최저가 순 투자, 모든 노드 상한 상태를 비교한다. 후기 체크포인트는 각 조건에서 R01부터 실제 이어온 것을 쓴다. fixture의 비교 투자 구성을 고를 때는 구매 가능한 최저가를 반복한다(동률 ID 서수). 다음 선택의 가격이 잔액보다 크거나 후보가 없으면 중단하고, 남은 골드·구매 목록을 기록한다. 최고 정산·해금·진화는 원본 후보에서 승계한다.
5. **판정** · 저장 또는 무구매 레거시 회귀, 중복 정산, 원본 공격 예산 누락, 보상/장비 획득 단절은 출시 차단이다. C7 기록(주무기 우선, 물맷돌, 시드 7, 치명 접촉 예측 0.30초)의 기준은 R101~180 일반 웨이브 최저 처치율 ≥33.74%, R180 보스 ≤900초로 확인한다. 기록값 34.25%(R175), 895.80초는 기존 자동 이동의 비교값이다. 강화·새 풀의 조정폭은 위 실측(처치율, 명중률, 피격, 레벨, 골드, 보스 시간, 대상별 최대 동시 개체 및 프레임 비용)을 수집해 구현 검토에서 확정한다. 수치를 정하지 못한 결과는 미판정으로 남겨 두며 출시 승인을 대체하지 않는다.
