## 첫 출시 범위

**첫 출시에 공통 세부 트리 12개와 무기별 트리 10개, 고유 노드 420종을 전부 포함한다.** 모든 노드를 미리 볼 수 있고 선행 조건과 진행 조건을 채우면 구매할 수 있다. 구매 효과는 새 도전부터 적용하며, 공통과 무기별 투자금을 한 번의 무료 전체 환불로 돌려받는다. 기초 공통 8종의 ID·30개 구매 단계·가격·선행 조건과 무기별 숙련·신속·특화의 기획 가격을 유지한다. 획득 범위 1단계와 물맷돌 추가 투석은 내부 검증에서 먼저 연결할 대표 사례다. [전체 트리 배분](../skill-tree.md#전체-규모와-작성-상태) · [무기별 300종 개요](../weapon-skill-trees.md)

무기별 트리는 회전 성경, 삼손의 턱뼈, 다윗의 물맷돌, 모세의 지팡이, 다니엘의 사자, 불기둥, 하늘의 번개, 십자가, 광야의 외침, 엘리야의 불수레를 모두 포함한다. 무기당 30종은 기초 5종, 고유 갈래 4개에 각 5종, 진화 연계 5종이다. 공통 공격력 1단계와 해당 무기의 영구 해금으로 숙련을 열고, 숙련 뒤 갈래가 열린다. 진화 연계는 해당 무기의 진화 업적으로 구매하고 도전 중 실제 진화했을 때 발동한다. 영구 구매는 시작 무기 선택과 전투 중 획득·진화 조건을 유지한다. [무기 가지 및 공통 조건](../skill-tree.md#무기별-가지) · [무기별 갈래 및 진화 업적](../weapon-skill-trees.md)

기존 이동속도의 획득 범위 2단계 조건과 경험치 획득량의 이동속도 1단계 조건은 트리가 달라도 지킨다. 화면에서 다른 트리의 선행 노드로 바로 이동할 수 있게 한다. 공통 112종은 효과 개요부터 작성해야 한다. 무기별 추가 270종은 효과 개요가 있고 수치·가격·해금 조건이 미정이다. 기초 38종의 합계는 21,950골드이며 420종 전체 가격은 미정이다. 구현 계획을 검토하기 전에 420종 표에 노드 ID, 최대 단계, 선행 노드와 진행 조건, 단계별 가격, 적용 가능한 무기·형태, 효과와 발동 시점, 보조·진화와의 합산 순서·상한, 재개 시 필요한 상태를 적는다. 각 노드는 빈 프로필에서 제시된 조건을 따라 도달할 수 있어야 한다.

현재 Core의 장착·공격 프로필·진화는 회전 성경·삼손의 턱뼈·물맷돌에 연결돼 있다. 나머지 무기 7종의 진행 해금 표기가 실제 장착·공격 구현을 대신할 수는 없다. 첫 출시에는 10종 모두 실제로 획득·사용·진화할 수 있게 하고, 영구 무기 해금은 기존 진행 조건을 활용한다. 출시 설계에서 7종의 공격과 보조·진화 조건, 전투 표현·효과 피드백, 성장·보스 선택과 저장에 필요한 연결을 구체화한다. `AttackProfile`은 현재 공통 공격력과 보조 효과를 조합하고, 진화 물맷돌 수량은 `max(5, 기본 수량 + 보조)`로 계산한다. 만렙과 보조 최대에서 현재 6발이며, 기획상 진화 수량은 기본 5 + 보조 2 + 특화 1로 8발이다. 특화를 기존 계산에만 더하면 7발이다. 진화 계산 변경이 필요한 새 도전 규칙과, 기존 도전 재개 시 보존해야 할 수량·연사 일정을 구현 전에 확정한다. 발사 수는 무기 레벨·장비 슬롯·진화 조건을 바꾸지 않으며, 다른 시작 무기를 선택한 뒤 도중에 물맷돌을 얻어도 도전 시작 사본으로 적용한다. ## 화면 흐름

1. **메뉴 → 영구 스킬트리.** 첫 시작과 사망 후의 시작 무기 화면, 책 완료, 일시정지에서 접근한다. 플레이 중 접근하면 일시정지하고 체크포인트 저장 성공 후 연다. 닫으면 들어온 화면으로 돌아간다. 살아 있는 도전은 기존 재개 버튼으로 이어 간다.
2. **공통·무기별 탭 → 노드 상세 → 구매.** 공통 탭에는 공격·생존·탐색과 세부 트리 12개, 무기별 탭에는 아이콘과 이름으로 구분한 10개 트리가 있다. 아직 해금하지 않은 무기도 트리를 살펴보고 무기 해금·숙련·진화 업적 중 어느 조건이 필요한지 확인할 수 있다. 잔액과 ‘새 도전부터 적용’을 계속 표시한다. 노드에는 현재 단계, 현재·다음 효과, 가격, 선행 조건, 구매 가능·골드 부족·최대 상태를 표시한다. 예를 들어 이동속도는 획득 범위 2단계가 필요하다. 활성 도전이 있으면 재개 시 시작 당시 강화가 적용된다고 안내한다.
3. **구매 결과.** 한 번에 한 단계만 처리한다. 클릭 당시 단계·가격과 저장 리비전을 실행 시 확인하고, 저장이 확인된 뒤에만 잔액·노드 상태를 갱신한다. 처리 중에는 버튼과 전투 재개를 막는다. 저장 실패나 결과 불명 시 완료 표시 없이 같은 실행 ID와 후보로 다시 시도하거나 디스크에서 결과를 확인한다. 리비전이 다른 저장으로 바뀌면 최신 상태를 다시 읽어 금액과 조건을 갱신한다. 실행 전 뒤로가기는 선택을 닫고, 실행이 시작되면 결과를 확인할 때까지 화면 이동을 막는다.
4. **전체 환불 → 금액 확인 → 환불.** 실제 반환액과 다음 새 도전 적용 문구를 표시한다. 취소는 확인창을 닫는다. 확인 시 반환액과 대상 랭크를 다시 확인한 뒤 골드 증가와 노드 초기화를 한 번에 저장한다. 구매 내역이 없으면 버튼을 비활성화한다. 저장 후에는 영구 해금·구약 완주 기록·현재 도전 체크포인트를 유지한다.

## 최소 플레이 시나리오

**검증할 가정** · 첫 노드의 가격을 자연스럽게 마련할 수 있고, 플레이어가 구매 효과를 관찰하며 ‘새 도전’과 ‘재개’의 차이를 이해할 수 있다.

| 순서 | 행동 | 관찰·통과 기준 |
| --- | --- | --- |
| 1. 골드 마련 | 골드 0의 격리 프로필로 물맷돌을 골라 R01을 플레이한다. R01에서 모자라면 같은 도전의 R02를 이어 간다. | 잔액 60골드가 처음 되는 라운드·시간과 실제 저장 잔액을 기록한다. R01 완료 고정 보상은 25골드라 60골드에는 175처치가 필요하다. 240마리 전부 처치한 73골드는 상한 예시다. |
| 2. 첫 구매 | 일시정지에서 스킬트리를 열어 획득 범위 1단계를 산다. 앱을 다시 열어 잔액과 단계를 확인하고 기존 도전을 재개한다. | 구매 전 잔액이 G라면 G−60, 획득 범위 1단계. 이동속도는 여전히 잠김. 기존 도전은 범위 0.70 월드 단위 유지. |
| 3. 새 도전 효과 | 기존 도전을 사망으로 끝낸 뒤 같은 시작 무기로 새 R01을 연다. 통제용 비교에서는 무강화와 같은 위치의 보석에 중심 간 거리 0.74까지 접근한다. | 기본 0.70에서는 보석이 남고, 구매 후 0.77에서는 보석이 들어온다. 화면에는 반경 +10%와 실제 습득이 확인된다. 통제 비교에서는 동일 입력·배치로 레벨업 선택 전에 관찰한다. |
| 4. 전체 환불과 적용 경계 | 강화된 도전을 일시정지해 전체 환불 창에서 먼저 취소하고, 다시 열어 확인한다. 재실행 후 그 도전을 재개한 뒤 사망 후 새 도전을 연다. | 취소 시 잔액·랭크 유지. 확인 시 직전 잔액 +60, 구매 랭크 0. 재개 도전은 반경 0.77과 기존 도전 ID를 유지한다. 새 도전의 반경은 0.70이며 영구 무기 해금과 완주 기록은 유지된다. |

구현 승인 후 PC 빌드에서 내부 플레이어 2명에게 각 15분 이내로 자연 획득과 화면 이해를 관찰한다. 통제용 플레이는 격리된 테스트 프로필에 보석 조건과 60골드 이상을 준비할 수 있다. 이 프로필로 자연 획득 시간을 판정하지 않는다. 첫 실험의 통과 기준은 두 플레이어가 R02 완료 이내에 첫 구매를 할 수 있고, 재개와 새 도전의 적용 차이를 설명하며, 통제 검증에서 구매·환불 경계가 모두 일치하는 것이다. R02까지 도달했지만 60골드를 얻지 못하면 첫 구매 안내·획득 경제를 재검토한다. 보석 거리나 저장 전후 잔액을 기록하지 못하면 해당 항목의 판정을 보류한다. 잔액 중복 차감·이중 환불·체크포인트 손실이 나오면 플레이 검증을 중단하고 재현 자료를 남긴다. 시간·인원은 첫 검증 예산 제안이다. 모바일 입력과 앱 중단·복귀는 실기기에서 별도 검증한다. [모바일 계획](../mobile-platform-plan.md)

무기별 연결의 첫 검증은 600골드 격리 프로필에서 공격력 1 → 숙련 → 추가 투석을 산다. 새 도전에서 1레벨 2발, 2레벨 3발, 만렙·보조 최대 7발, 합산 규칙을 확정한 진화에서 8발을 확인한다. 다른 시작 무기에는 특화 효과가 없어야 하고, 물맷돌을 도중에 얻으면 같은 도전 사본을 사용해야 한다. 공통 공격력과 물맷돌 노드를 함께 환불해 600골드가 돌아오는지, 연사 도중의 저장·복원이 일치하는지 확인한다. 출시 검증에서는 시작 무기 3종에 더해 진행으로 처음 열리는 무기와 후기 무기를 대표로 골라 해금 → 전투 획득 → 첫 진화 → 진화 연계 노드 구매 → 다음 도전에서 진화 후 발동을 플레이한다. 실제 획득은 R04 누적 표의 611골드와 별도로 측정한다. ## 저장 호환성

- **저장 버전** · 기존 공통 키 8개와 가격·효과는 유지한다. 공통 112종과 무기별 300종은 새 키가 필요하므로 기존 `PermanentRules.Validate`를 확장하고 저장 버전 전환을 설계한다. 구 빌드는 같은 버전의 낯선 키를 손상으로 보고 `.bak`를 읽을 수 있다. 확장 저장은 구 빌드에서 미래 버전으로 거절하고 원본과 백업을 보존하는지 확인한다. `Profile.Gold`와 `Profile.Upgrades`는 하나의 체크포인트로 커밋하고, `Run.PermanentSnapshot`은 새 도전에서만 복사한다. 기본 환불은 고정 가격표가 실제 지불액과 같을 때 유효하다. 새 노드의 가격을 출시 후 변경할 계획이면 실제 지불액을 복원할 수 있는 기록 방식을 먼저 결정한다. 조건부 효과의 발동 횟수·지속 시간처럼 이어 하기에 필요한 상태도 설계에서 확인한다. 구매·환불은 `SaveStore`의 리비전·실행 ID·원자적 교체를 활용한다. 전투 중단 저장을 먼저 확정하고, 프로필 변경 후보의 저장·읽기 확인 뒤에만 Host 상태를 갱신한다. 새 도전·자동 저장·보상 정산과 동시에 쓸 수 없게 한다. [저장 트랜잭션](../../src/BibleSurvivor.Core/SaveState.cs#L301) · [Host의 후보 저장 재시도](../../UnityGame/Assets/Adam/Runtime/AdamHost.cs#L243)
- **회귀 표본** · schema 1·2의 R02 fixture와 schema 3의 R60·R170·R180 완료 저장을 읽는다. 공통 구매가 들어 있는 과거 저장과 구매 랭크가 없는 저장을 모두 포함한다. 로드 시 새 공통·무기별 노드의 랭크는 0으로 해석하고, 구 저장에서 구매한 단계와 기존 도전의 강화 사본을 유지한다. 잔액·해금·도전 ID·전투 사본·보스 기록·`OldTestamentClear`를 대조한다. schema 1은 현재 메모리 변환과 첫 쓰기 전 원본 보관을 확인한다. R170은 R171을 이어 가고, R180은 R181 진입 제한과 구약 완주 기록을 유지한다. 저장 전 실패, 커밋 후 읽기 실패, 더블 클릭, 오래된 리비전, 취소, 재실행을 각각 재현해 중복 차감·환불·보상 지급이 없고 재개 상태가 보존되는지 확인한다. ### 1단계에서 확정할 데이터

- **노드 행** · 고정 ID, 표시명, 공통 분류 또는 무기·갈래, 최대 단계와 단계별 가격, 선행 노드·필요 랭크·진행 및 업적 조건, 적용 무기·기본형·진화형, 효과 수치와 단위, 발동 조건·지속·내부 대기·중첩 상한, 저장 필요 상태, 정상·경계 검증 사례. 예시로 `pickup`의 1단계는 60골드·기본 해금·도전 시작 시 반경 ×1.10·거리 0.74의 보석 습득이다. 추가 투석은 350골드·물맷돌 숙련 필요·주기당 +1발이며, 신규 고정 ID와 진화 합산 정책을 함께 확정한다.
- **무기 행** · 고정 ID, 영구 해금 라운드, 성장 선택 및 획득 경로, 레벨 1~8의 피해·주기·수량·사거리와 표적·충돌 규칙, 진화 보조와 후보 노출 조건, 진화 시 교체할 기본 수치와 계승할 보너스, 월드 저장 상태, Unity 표현에 필요한 에셋. 무기·보조 조합과 진화 업적이 실제 캠페인에서 도달 가능한지 확인한다. [무기 성장의 현재 정의](../../src/BibleSurvivor.Core/Growth.cs#L140) · [진화 규칙](../../src/BibleSurvivor.Core/EvolutionRules.cs)
- **합산 계약** · 기본 장비 레벨 또는 진화형의 수치를 선택하고, 같은 능력치에 해당하는 공통·무기별·보조 합산 규칙과 상한을 적용한다. 조건부 효과는 발동 순서와 재발동 가능한 공격 출처를 명시한다. 구현 전에 무강화 진화 수치의 보존 기준, 첫 장비 획득과 진화가 가능해지는 시점, 출시 밸런스 허용폭을 정한다. [현재 공격 계산](../../src/BibleSurvivor.Core/Combat.cs#L27) · [무기 노드 수치화 조건](../weapon-skill-trees.md#수치화할-때-지킬-범위)

### 저장 전환과 명령 경계

1. **읽기** · 과거 schema 1·2·3의 파일을 읽고 새 노드의 랭크는 0으로 해석한다. 예전 도전은 기존 무기 후보 풀·보상 규칙·영구 효과 사본으로 재개한다. 새 저장 버전과 도전에 고정할 전투 규칙 버전의 역할을 명세한다. 현재의 창세기 시작·책 진입 경로가 저장 버전을 각각 설정하므로, 이미 전환한 파일이 어느 경로에서도 구버전으로 되돌아가지 않는지 확인한다. [저장 형식 판별](../../src/BibleSurvivor.Core/SaveFormat.cs) · [도전 시작과 책 진입](../../src/BibleSurvivor.Core/AdamSession.cs#L93)
2. **구매·환불** · 명령은 노드 ID·표시 랭크와 가격 또는 환불 대상·예상 반환액·저장 리비전을 받는다. Core에서 다시 검증한 뒤 후보 사본의 잔액과 랭크를 함께 저장한다. 가격표는 기존 8종의 지불액 복원에도 쓰인다. 가격 변경에 대비할 경우에는 기존 8종 금액을 이전 가격표로 복원하고, 새 구매부터 실제 지불액을 기록하는 안을 검토한다. 환불 시 남은 영구 해금·진화 업적과 활성 도전 사본을 보존한다.
3. **실패·재시도** · 저장 전 실패면 확정 잔액을 계속 표시한다. 커밋 결과를 모르면 같은 실행 ID로 커밋 결과를 읽어 확인한다. 결과가 확인될 때까지 다른 구매·환불·전투 재개가 대기한다. 리비전이 달라졌다면 최신 상태로 화면을 다시 열고 가격·조건을 재확인한다. 중복 클릭과 취소도 이 경계를 기준으로 시험한다.
4. **검증 경계** · `SaveFormat`의 허용 필드와 버전 검사, `SaveState`의 보상·레벨업 후보 검증, `BattleWorld`의 무기·투사체·발사 일정 복원, Unity의 `AdamCatalog.ForCheckpoint`를 함께 검토한다. 기존 저장은 일반 전투, 성장 선택 대기, 골드 대체 보상, 보스 보상 대기, 책 경계, R180 완료 상태에서 각각 이어 간다. [저장 형식과 보상 후보](../../src/BibleSurvivor.Core/SaveState.cs) · [전투 복원 테스트](../../tests/BibleSurvivor.Core.Tests/BattleSaveTests.cs)

### 구현 전 기준선 재현

- 새 이슈가 잡은 기준 커밋 SHA와 Unity 버전·테스트 환경을 기록한다. 게임 코드를 수정하기 전에 같은 환경의 격리 프로젝트에서 전체 PlayMode를 실행해 XML과 Editor 로그를 보존한다. 그래프 이슈 #39의 전체 PlayMode 기록(38/40, 기준판과 같은 R01 이펙트 실패 2건)은 비교에 사용한다. 새 기준에서 실패하는 항목은 이름·메시지·실패 위치를 기록하고 해당 시험만 다시 실행해 재현 여부를 확인한다.
- 구현 후 완성 커밋에서 같은 절차를 반복해 시험별 결과를 비교한다. 기준 커밋에서 재현한 실패만 기존 실패로 분류하고, 새 실패와 달라진 실패는 조사한다. 환경 제약으로 기준을 재현할 수 없으면 확인하지 못한 것으로 기록한다.
- Core 검사와 시뮬레이터는 같은 Core 프로젝트를 빌드한다. 같은 체크아웃에서 기본 출력을 쓸 때는 순차 실행한다. 병렬 실행이 필요하면 명령마다 별도 `--artifacts-path`를 사용하거나 격리 체크아웃에서 돌린다. 실패 시 종료 코드와 원본 로그를 보존하고, 작업 중에는 요약과 실패 지점만 읽는다.
