# 전투 타격감 개선 계획

2026-11-14. 사용자 실제 플레이 피드백: “타격감과 이펙트가 좀 부족한거 같아”. 기준84ccd91, 계획 단계이며 새 효과/사운드 구현·실측은 아직 하지 않았다. 현재 사용자 iOS 플레이는 건드리지 않는다. 독립 리뷰는 최신 사용자 지시대로 PC에서 수행한다.

## 현재 관측

`AdamArtWorld.Update/Draw`에는 명중 스파크·적 사망 파편·성경 광륜·턱뼈 궤적·물맷돌 잔상이 있다. 전투는 Core snapshot을 읽어 표시한다. 살아 있는 적의 이전/현재 체력을 비교해서 명중 효과를 만들기 때문에 치명타격으로 사라진 적에는 명중 스파크가 빠질 수 있고, 한 표시 갱신 사이의 여러 명중도 합쳐진다. 현재 표시 정보만으로 무기별 명중 원인/정확한 충돌점을 확정할 수 없다. 이것은 코드 관측이며 실제 프레임별 영상 계측은 미실행이다.

## 우선 적용할 연출

아래 시간/크기는 첫 비교 빌드의 조정값이며 합격한 밸런스·성능 수치가 아니다. 전투 피해·공격 간격·충돌·적 실제 위치·저장 진행은 바꾸지 않는다.

| 상황 | 화면 | 소리 | 첫 조정값 |
| --- | --- | --- | --- |
| 일반 명중 | 맞은 적만 밝은 색으로 짧게 강조하고 충돌점에 방향성 스파크 | 무기별 짧은 명중음 | 강조50~70ms, 스파크80~120ms |
| 무거운 명중 | 적 스프라이트의 짧은 눌림/복원과 파편 | 낮은 충격음 한 겹 | 변형80~100ms, 발 위치·판정 유지 |
| 처치 | 마지막 명중 강조→적 파편→XP 등장 순서를 명확히 표시 | 작은 처치 꼬리음, 동시 처치 묶음 처리 | 파편150~220ms |
| 플레이어 피격 | 캐릭터 강조와 HUD 체력 감소 강조 | 적 명중음과 다른 경고음 | 강조80~100ms, 강도 조절 |
| 경험치 획득 | 보석이 닿는 작은 빛과 XP 게이지 짧은 반응 | 짧고 낮은 수집음 | 연속 수집의 소리/입자 수 제한 |
| 레벨업 | 전투 정지와 함께 플레이어 주변 링·카드 등장 | 짧은 상승음 | 전투 시야를 덮지 않는 일회성 |

기본 공격마다 전체 화면을 멈추는 연출은 초기 적용에서 보류한다. 군중 전투에서는 반복 정지가 이동·회피감을 바꾸기 때문이다. 이후 비교안은 턱뼈 강타의 국소 표현 정지30~40ms만 후보로 두며 Core tick/공격·저장 시계는 그대로 유지한다. 연출 시계와 논리 시계가 섞이지 않는 검사가 먼저다.

## 세 시작 무기의 차이

| 무기 | 공격 전/발사 | 명중 | 처치/성장 체감 |
| --- | --- | --- | --- |
| 회전 성경 | 짧은 금빛/상아색 곡선 잔상, 책 전면과 회전 방향이 보임 | 접선 방향 빛 조각·맑고 짧은 종이/금속성 소리 | 얇은 빛 파편. 권수 증가는 책 개수·간격에서 읽힘 |
| 삼손의 턱뼈 | 짧은 준비 동작 후 넓은 한쪽 호의 휘두름 | 굵은 충돌 모양·뼛조각/먼지·낮은 타격음 | 셋 중 가장 무게 있는 눌림/복원. 연타 증가는 구분되는 휘두름 |
| 다윗의 물맷돌 | 발사 순간 짧은 선·작고 선명한 돌·속도 방향 잔상 | 작은 점 충격→돌가루가 진행 방향으로 흩어짐 | 관통하면 각 적 충돌점에서 작은 반응, 발사 수 증가는 궤적에서 읽힘 |

피해 숫자는 선택 설정으로 제공하는 후속 후보다. 기본 화면은 적 실루엣·충돌점·무기 궤적이 잘 보이게 하고, 같은 적의 연속 숫자는 짧게 합산하는 비교안을 만든다. 치명타 시스템은 아직 없으므로 큰 타격을 임의로 치명타라고 표시하지 않는다. 실제 넉백/새로운 피해 효과는 별도 전투 설계 변경이다.

## 표현과 사건 전달

1. 치명 명중을 포함한 사건을 정확히 전달한다. 첫 단계는 현재 위치/체력 차분의 한계를 재현한다. 무기별 원인·충돌점·같은 tick 여러 명중을 구분하려면 실제 Core 명중 지점에서 단조 증가 sequence·tick·weaponId·enemyId·position·실제 피해·killed를 담은 일시적 사건 스트림이 필요하다. 저장 schema/난수/피해 결과를 바꾸지 않으며 구현 범위는 별도 작은 변경으로 묶는다.
2. 같은 사건은 표시 갱신에서 한 번만 소비한다. OnGUI의 Layout/Repaint 재호출, pause→resume, snapshot 재로드/새 World에서 소리·파편을 중복 재생하지 않는다. 로드 직후 과거 명중은 재생하지 않는다.
3. 기존64슬롯 표현 풀을 활용하되 명중·처치·플레이어 경고 우선순위를 분리한다. 포화 시 장식 잔상부터 줄이고 중요한 피격 단서는 보존한다. 소리도 동시 발음 상한·무기별 짧은 재생 간격·화면 밖 감쇠를 둔다. 작은 무작위 pitch는 Core 난수와 분리한다.
4. 흔들림은 후속 선택 기능으로 약하게 시험한다. 움직이는 것은 전투 화면이며 HUD·모달·버튼 좌표는 고정한다. 기본/약함/끔 및 저효과 옵션을 제공하고 전체 화면 반복 섬광은 사용하지 않는다. 모바일 햅틱은 켜고 끌 수 있는 후속 후보이며 실기기 검증 전 지원 완료로 표시하지 않는다.

## 제작·개발 순서

- P0: 정확한 명중/처치 사건→피격 강조·작은 변형→세 무기 타격음·스파크. 기존 효과와 같은 카메라·동일 seed·같은 피해 결과로 A/B 영상을 남긴다.
- P1: 무기별 잔상·사망 파편·XP/레벨업 반응과 저효과/음량 설정. 아트는 `art/combat-fx-brief.md`로 Claude Design 제품 담당에게 인계한다. 현재 세션에는 해당 제품 도구 연결이 확인되지 않았으므로 브리프 준비만 완료이며 Design 제작 실행으로 보고하지 않는다.
- P2: 선택 피해 숫자·미세 흔들림·햅틱·국소 표현 정지 비교. 가독성/프레임 측정과 사용자 체감 확인 후 채택한다.

현재 Android 구현자가 Unity 파일을 소유하므로 이 계획만으로 병렬 제품 수정을 시작하지 않는다. Android 인계 후 표현 담당 단일 작성자로 배정하거나 R02 표현 작업과 파일 경계를 합의한다. 유료 사운드/에셋 구매는 승인 없이 하지 않으며 원본 제작/사용권이 확인된 소스만 사용한다.

## PC 수용·회귀·GC

처음 체감 비교는 성경·턱뼈·물맷돌 각20~30초 같은 장면으로 한다. 무음/소리 포함·기본/저효과를 비교하고 명중과 빗나감, 단발 처치, 연속 관통, 다수 동시 처치, 플레이어 피격을 구분할 수 있는지 검토한다. 적40/120 구간은 실제 Frame time·할당·발음 수를 측정하고 수치 없이 “최적화 완료”라고 하지 않는다.

동일 입력/seed에서 전후 Core snapshot·HP/처치/XP/골드·저장 bytes가 같아야 한다. 치명 명중 누락·복수 명중 합침·중복 UI pass·정지/복귀·로드 직후 재생·풀 포화·효과 끔에서도 경고 단서 보존을 검증한다. 원래 누락/중복 구조 변이는 행동 시험에서 실패해야 한다. 별도 PC 코드/시청각 리뷰→수정/재검토→프로젝트 GC→commit/push/해당 SHA CI로 마무리한다. PC PASS를 Android/iOS/실물 성능 PASS로 옮기지 않는다.
