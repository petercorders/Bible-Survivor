# R02 엔진 독립 코어 — 독립 코드 리뷰

2026-11-14 KST. 구현 담당과 별도 세션의 읽기 전용 리뷰다. 기준은 `a0206c6` 이후 R02 작업트리이며 Unity 프로젝트/그래픽 작업은 별도 담당 범위다.

## 결론

검토 범위에서 신규 HIGH/MEDIUM 결함을 발견하지 않았다. R01→R02 연속 진행의 상태 보존·아레나 초기화·중복 전환 거절·완료 보상·저장 복원·카탈로그 변경 거절은 코드와 격리 행동 시험으로 확인했다. 이는 Unity/모바일 플레이·성능·난이도 검증 통과를 뜻하지 않는다.

## 검토 범위와 판단

- `AdamSession.cs`: `IsCurrent`가 현재 도전 참조와 라운드/단계를 함께 확인한다. `StartNextRound`는 완료·선택 처리·다음 번호를 검사하고, 새 Wave를 만든 뒤 이전 World/드롭/피격 시계를 초기화한다. 완료 시 보상·해금은 해당 정의를 사용하며 이전 세션의 Advance/Choose/Capture는 새 라운드를 오염시키지 않는다. R03 진입은 거절하고 완료 대기만 보존한다.
- `SaveState.cs`: 지원된 단계/번호와 fingerprint의 legacy 허용 범위, 완료 상태의 전부 회복/빈 드롭, 피격 시계와 새 라운드 시계 관계를 확인했다. 기존 revision/operation ID 거래·쓰기 실패·백업·미래 schema 및 World 교차 정합 검사는 유지된다.
- `Waves.cs`, `CatalogReader.cs`: R02의 실제 정의/ID/웨이브/몬스터/예산/상한/골드/해금을 소비한다. fingerprint에 라운드 ID·번호·상한·XP·골드·해금·시간 구간·몬스터 ID/개수/체력/접촉 피해를 포함한다. 변경된 미래 웨이브로 진행 중 저장을 재개하는 경로를 별도로 시험했다.
- `RoundTransitionTests.cs`: 미완료·사망·미처리 선택·번호 오류·반복 전환 거절, 성장/장비/영구 스냅샷/처치 나머지 보존, 새 World·피격 시계, 이전 session/world 무효화, 저장 실패/불명 결과 재시도, legacy 및 카탈로그 변경 시험을 검토했다.
- `SeriesRunner.cs`, `Program.cs`, `BattleRunner.cs`: 주입 예산 모드와 좌표 전투 모드를 구분한다. 좌표 모드의 PASS는 타임아웃을 포함한 정상 완료/저장·연속 전환 조건이다. 실제 처치 수를 함께 출력하므로 R02 근접 무기 0킬을 전멸/밸런스 통과로 표시하지 않는다. 사망/미완료는 R03 대기 조건을 충족하지 못해 실패한다.
- `check_all.py`, `check_mutations.py`: R01 기존 실행을 유지하며 연속 모드를 추가했다. 테스트에 연결된 실제 reader/content를 격리 사본에도 복사한다. 실패 종료 코드를 유지하고 변이는 별도 사본에서 원복하며 컴파일 오류를 행동 회귀 검출로 세지 않는다.

## 독립 실행과 원회귀 검증

공유 작업트리/검사 러너 충돌을 피하기 위해 `src`, `tests`, `content`, CLI reader 및 SDK 설정을 임시 사본으로 복사했다. 원본 소스·시험·설정은 수정하지 않았다. 기존 로컬 .NET SDK를 사용했고 새 SDK/패키지를 설치하지 않았다.

| 실행 | 실제 결과 | 의미 |
|---|---|---|
| 격리 사본에서 `dotnet run --project tests/BibleSurvivor.Core.Tests -- --results evidence/review-baseline` | exit 0, 86/86 PASS | 기존 84개와 리뷰어가 격리 사본에만 추가한 경계 시험 2개 |
| 이전 세션의 `IsCurrent` 라운드 검사를 제거한 변이 | exit 1, 행동 시험 FAIL | 이전 세션의 성장/장비 변경·Capture·피해·반복 전환이 새 세션에 영향을 주는 회귀를 실제 검출 |
| 저장 fingerprint 비교를 제거한 변이 | exit 1, 행동 시험 FAIL | 아직 생성되지 않은 R02 후반 몬스터 접촉 피해가 바뀐 정의로 Resume하는 회귀를 실제 검출 |

두 독립 경계 시험은 (1) R02 진입 후 이전 R01 핸들의 성장/장비 변경과 Capture/치명 피해가 현재 도전을 덮어쓰거나 죽이지 못함, (2) 전투 시작 전이라도 후반 웨이브 접촉 피해 변경을 fingerprint가 거절하고 기존 잔액/시계를 유지함을 확인한다. 이 시험 코드는 검토용 임시 사본에만 있으며 기존 저장소의 84개 시험 수에 합산하지 않는다.

각 변이는 원문 위치를 확인한 뒤 동일 사본에 하나씩 적용했고 `finally`에서 복원했다. `FAIL` 메시지와 비영 종료를 확인했으며 `error CS`가 없는 행동 실패였다. 이 리뷰에서 기존 18개 변이/전체 14개 CLI를 모두 반복 실행했다고 주장하지 않는다. 구현 담당의 전체 실행 근거는 R02 진행 문서에 별도로 있다. 독립 실행의 JSON/XML/변이 로그 위치는 coordinator에게 인계했다.

## 한계·남은 게이트

- fingerprint 없는 legacy R01 저장은 이후 웨이브 변경을 완전히 탐지할 수 없다. R02 진행/완료 저장에는 fingerprint를 요구하고 이전 실행기로의 downgrade를 제공하지 않는다는 경계가 문서화돼 있다.
- World 없는 저장을 읽는 것은 좌표 복원 검증과 다르다. 실제 World 왕복·동일 입력의 결정성 시험은 World가 포함된 체크포인트에 적용된다.
- wilderness_voice/lightning은 해금 상태만 구현됐고 실제 장착/공격 풀은 시작 무기 3종이다. R03 보스와 이후 라운드·추가 무기·스킬 420종은 이번 리뷰의 구현 완료 범위가 아니다.
- Unity Editor 컴파일·플레이·모바일·실기기 수명주기·프레임/메모리·원격 CI는 이 독립 리뷰에서 NOT_RUN이다. 병행 Unity 작업의 결과를 본 코어 리뷰 결과로 대체하지 않는다.
- 실제 모델별 usage·토큰 절감률은 미측정이다. 원본 변경 파일만 읽고 필요한 코어 시험/두 원회귀만 격리 실행했으며 별도 에이전트를 생성하지 않았다.
